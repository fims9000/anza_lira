# CT28: точная проверка 3D ANZA-патчей в миллиметрах

Проверено реальным запуском GitHub Actions **2026-11-03**, [workflow #41614200633](https://github.com/fims9000/anza_lira/actions/runs/41614200633); [машиночитаемый артефакт](https://github.com/fims9000/anza_lira/actions/runs/41614200633/artifacts/13220906301). Код: `ct28_3d_patch_fov_audit.py` с `PatchConfig(side=24, voxel_mm=1)`.

Это **геометрический эксперимент** на сохранённых endpoint-координатах, а не работа с исходными медицинскими КТ. Вход: 1 404 сцены, 7 020 endpoint-записей, 15 092 пары/тройки кандидатов (17 train/5 validation субъектов). Для каждого кандидата вычислялась реальная ортонормальная локальная система 3D ANZA; подписанный запас до ближайшей грани патча равен

```text
margin_mm = (side - 1) * voxel_mm / 2 -
            max(|endpoint_coordinate_in_local_frame|)
```

При `margin_mm >= 0` все координаты endpoints находятся внутри патча, хотя **сама КТ-область вокруг них может выходить за границы исходного тома**. Для этого есть отдельная проверка `sampling_inside_volume_fraction`.

| Источник | Кандидатов в чистом наборе | Вне 24 мм (clean) | Переменных с 15 возмущениями | Вне патча после возмущений |
|---|---:|---:|---:|---:|
| Train PAIR | 6 336 | 0 | 95 040 | 0 |
| Train JUNCTION | 4 685 | 0 | 70 275 | **2** |
| Validation PAIR | 2 298 | 0 | 34 470 | 0 |
| Validation JUNCTION | 1 773 | 0 | 26 595 | **1** |
| **Все** | **15 092** | **0** | **226 380** | **3** |

При 0.8 мм случайных сдвигах и 20° угловых возмущениях (15 повторений для каждой сцены, seed 20260920) 3 из 226 380 candidate instances выходят за физический ROI. Это **очень редкий**, но реальный источник некорректной входной карты endpoints. Минимальная измеренная дистанция для таких случаев — −0.465 мм. На первоначальном чистом train JUNCTION минимальный запас +0.888 мм, val JUNCTION +1.252 мм. PAIR имеют запас не менее 5.50 мм на чистом наборе.

## Реализованное защитное поведение

- `extract_candidate_patch` возвращает `endpoint_patch_margin_mm` и `all_endpoints_inside_patch`, не меняя состав двух входных каналов CNN/ANZA.
- `build_patient_cache` сохраняет число непокрытых endpoints и минимальный физический запас для исходного 3D-патча пациента. `load_type` не разрешает обучаться на новой кэшированной выборке с заведомо неполными endpoint heatmaps — сначала нужно выбрать заранее определённый другой физический размер патча и пересобрать обе модели.
- **На этапе inference**, если хотя бы один candidate endpoint находится за пределами 3D heatmap ROI, модель **отказывается от ремонта всей сцены**, даже при высокой оценке связи. Это контролируемый консервативный abstention, а не новая клиническая гарантия.
- Для восстановления exact 1+15 **train augmentation** старого протокола rare truncated inputs пока сохраняются (вместо изменения количества/весов обучающих сцен), но новое поле `train_augmented_candidate_patches_with_truncated_endpoint_heatmap` фиксирует их число. Требуется отдельно сравнить корректную mask-based обработку недостающего endpoint признака. Для selected K10/15 ничего не меняется.

**Не заявлять:** 24 мм — оптимальный размер для всего настоящего объёма или любой будущей маски; проверка относится только к нынешней CT28 геометрии искусственно созданных кандидатов. На естественных ошибках segmentation кандидаты могут находиться значительно дальше друг от друга, и новая анатомическая протокольная проверка остаётся обязательной.
