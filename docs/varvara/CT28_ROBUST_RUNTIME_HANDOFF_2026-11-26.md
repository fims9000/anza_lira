# CT28 ImageCAS — исправление отказов каскада, 26.11.2026

## Что изменено

Это исследовательское ответвление, не замена замороженного K10/15. На исходном seed 20261102 в 22 окнах целых масок основная потеря происходила на HGB (CNN 19/22, ANZA 21/22, K10/15 22/22). На 368 подготовленных сценах значительная потеря правильных решений происходила при consistency. Поэтому введены два независимых изменения.

1. `--endpoint-jitter-mm 0.8`: на каждом train-batch с вероятностью 0,5 возмущаются отдельные карты концов, CT и dense target сдвигаются согласованно с новым центром. Только fixed LPS и separate tips; тот же бюджет эпох для CNN и ANZA. Это приближение на кешированном патче (краевые воксели экстраполируются nearest), а не точное пересэмплирование всей КТ. Ranking-пары в дополнительном loss остаются clean.
2. `--runtime-window-training`: добавляет к 1036 контролируемым train-сценам окна, извлечённые тем же runtime из искусственно повреждённых масок 17 train-пациентов. Метки PAIR/NONE определены по точному удалённому объёму и соприкасающимся компонентам; неоднозначные окна исключены с отчётом. Не меньше 8 пациентов с положительными окнами, 15 положительных и 15 отрицательных окон. Локальные скоры получены строго моделями OOF, исключавшими соответствующего пациента. 1 clean + 15 возмущений; добавленный домен получает суммарно такой же вес, как исходный, с равными весами пациентов. Это PAIR-ориентированная адаптация, не новая разметка JUNCTION.

Порог HGB 0.85, consistency 9/15, path v2, radius 0, ограничения реконструкции, пять development-validation масок и 6 закрытых held-out пациентов не изменены. Улучшение не предполагается заранее.

## Первый запуск — без переобучения CNN и ANZA

Используем уже обученные OOF-модели seed 20261102, ranking_weight=0, исходные separate-tip CNN и ANZA. Проверяем только адаптацию HGB. Путь `OLD` должен содержать четыре директории `oof_pair_conv3d_sep_structure`, `oof_junction_conv3d_sep_structure`, `oof_pair_anza3d_sep_structure`, `oof_junction_anza3d_sep_structure`. Если локальная структура отличается, укажите фактический каталог, не переносите чужие веса.

```bash
git fetch origin
git switch experiment/ct28-robust-endpoint-training-2026-11-26
source .venv-ccta/bin/activate

R=varvara/anza_lira_local_results
S=scripts/research/ccta_graph_lira_safe_repair
OLD="$R/ct28_structure_step3_seed_20261102/outputs"
FREEZE="$R/ccta_3d_validation/frozen_dev_val_20261103.json"

python "$S/run_ct28_robust_experiment.py" \
  --arm windows-only --seed 20261102 --device mps \
  --reuse-oof-root "$OLD" --freeze "$FREEZE" \
  --root "$R/ct28_robust_windows_seed_20261102" --window-audit
```

Если веса на другой машине, вместо `mps` используйте фактически доступное `cuda` или `cpu`. Скрипт проверит SHA, seed, параметры обучения и тип моделей, скопирует OOF-каталоги в новый корень, обучит новый HGB, прогонит все 5 масок, выполнит oracle и диагностику. Старые файлы не перезаписываются. При успешном повторном запуске готовые стадии переиспользуются; неполный/повреждённый результат не затирается.

## Второй эксперимент — устойчивые энкодеры

Если первый запуск показывает отказы consistency, используйте тот же проверенный fixed-LPS separate-tip cache, созданный ранее; задайте его точный локальный путь переменной CACHE. Не подбирайте пороги по development-validation.

```bash
python "$S/run_ct28_robust_experiment.py" \
  --arm combined --seed 20261102 --device mps \
  --cache-dir "$CACHE" --freeze "$FREEZE" \
  --root "$R/ct28_robust_combined_seed_20261102" --window-audit
```

Отдельный `--arm jitter-only` изолирует изменение энкодера. Для повторов 20261103 и 20261104 используйте те же параметры и отдельные корни. Опциональный `--deepsets` применяется симметрично к обеим моделям; `--ranking-weight 0.5` — отдельная абляция, не смешивать с ranking=0. При использовании старых весов указывать соответствующий старый root. Три seed с разными arm, ranking или jitter объединять запрещено.

Oracle использует эталон только для выбора заведомо подходящего кандидата и оценки, не является результатом метода. Проверяется независимое восстановление каждого разрыва; не следует трактовать это как число разрывов, которые можно одновременно восстановить с глобальными ограничениями. Реальное восстановление засчитывается только при уникально размеченной паре, принятом правильном кандидате, связности его концов и пересечении удалённой области. Неоднозначные разрывы не считаются подтверждёнными; указываются отдельно. На radius=0 восстанавливается линия, а не весь просвет. Число восстановленных вокселей и ложные/неожиданные связи обязательны. Не заявлять преимущество ANZA по одному seed или по одному только AUROC.
