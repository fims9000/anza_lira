# ANZA-LIRA — пузырьковая камера: состояние на 8 ноября 2026 года

## Задача

По оригинальным снимкам пузырьковой камеры выделять все видимые линейные структуры, сохранять их геометрию и координаты, различать **визуальные** типы объектов, предлагать возможное продолжение разорванных линий и готовить материал для проверки физиками. Нельзя путать обнаруженный штрих с физически установленным треком отдельной частицы. Работа ведётся отдельно от веток КТ и коронарных сосудов.

**Единая рабочая ветка:** `research/bubble-chamber-graph-lira`. Она включает последовательную историю S92–S101 (бывшие PR #8–#19); не нужно переключаться между отдельными `feature/bubble-...` ветками.

## Реализовано

1. **S86/S87** — обработка полноразмерного BMP по фрагментам, выделение бинарных кандидатов/центральных линий; учёт стыков тайлов. Это высокая полнота *кандидатов*, а не отбор только истинных треков.
2. **S92/S101** — видимая кривизна, завитки, концы линий, гипотезы соединения через разрывы. S101 отдельно оптимизирует набор *тех же* S92 предложений при ограничениях на порты и циклы. Соединения остаются гипотезами.
3. **S94/S95** — привязка операторских меток и предварительная классификация *каждого сохранённого* компонента. Основной визуальный тип и дополнительные признаки в `all_source_fragment_types.ndjson`.
4. **S96/S100** — кандидаты на геометрические пересечения, отдельные подходы для распознанных четырёхрукавных X; визуальные X не обязательно реперы и не доказывают столкновения.
5. **S97–S99** — инструменты независимой ручной оценки исходной фотографии, геометрической связности и ошибки отбора/морфологии.
6. **Реальный запуск** — одна команда на локальном исходном H50Z BMP с проверкой SHA, сохранением исходных фрагментов и небольших приватных пакетов для слепой проверки.

## Шесть машинных типов S95

| Значение | Как понимать |
| --- | --- |
| `CALIBRATION_CROSS_CONTEXT` | Кандидат рядом с уже отмеченным человеком репером; это ещё **не автономная детекция крестов** |
| `TRACK_LIKE_CANDIDATE` | Линейный фрагмент, похожий на след частицы |
| `ARTIFACT_LIKE_CANDIDATE` | Похожий на царапину, волосок или короткий угловатый артефакт |
| `BUNDLE_OR_INTERSECTION_REVIEW` | Скопление/пересечение фрагментов: пучок или наложение пока не различены |
| `COILING_TRACE_CANDIDATE` | Завиток либо изогнутый след на плоскости фотографии |
| `UNKNOWN` | Неоднозначный фрагмент, в том числе короткий гладкий возможный трек |

Это **взаимоисключающие основные категории для просмотра**, а `all_morphology_tags` могут содержать сразу несколько признаков. Даже `ARTIFACT_LIKE_CANDIDATE` не удаляется автоматически.

## Что означают «лишние объекты» и «один цвет»

На этапе S86 специально сохранены мелкие штрихи, царапины и шумоподобные кандидаты ради полноты. S95 их *размечает*, а не очищает; поэтому при включении **всех** объектов картинка может выглядеть более замусоренной. Рост числа найденных компонентов не равен росту точности.

**Не путать изображения:** `S93_SOURCES/H50Z_S92_annotated_small.jpg` показывает геометрию S92, но не шесть категорий S95. Для категорий открыть `S95_ALL_OBJECTS/index.html` и `S95_ALL_OBJECTS/S95_all_classes_comparison.jpg`, а также `S95_ALL_OBJECTS/report.json` с `all_extracted_line_categories.categories`. В S95 цвета различаются по `PALETTE_BGR`; если всё выглядит одинаково, сначала проверить распределение категорий и какой файл реально открыт, а не объявлять многоклассовую модель отсутствующей.

## Что на самом деле с физикой

Сейчас есть **двумерные геометрические ограничения**, кривые, вычисление поворота, граф возможных связей и необязательные привязанные к конкретному BMP **операторские** параметрические параболы (S95: `--operator-curves`). Если операторских кривых нет, они не возникают самостоятельно.

**Нет проверенного вывода массы, заряда, импульса, направления частицы, типа взаимодействия, 3D реконструкции или физической проверки по калибровке и магнитному полю.** По одному BMP такие параметры вообще нельзя надёжно восстановить. Геометрическую аппроксимацию некорректно представлять готовой физической моделью.

## Воспроизводимый локальный запуск

```bash
git fetch origin
git switch research/bubble-chamber-graph-lira
git pull --ff-only origin research/bubble-chamber-graph-lira
python -m pip install numpy scipy scikit-image opencv-python-headless networkx scikit-learn
python scripts/research/bubble_chamber/physicists_real_h50z_reproduce.py run \
  --bmp /PRIVATE/H50Z/H50Z_030_01_405.bmp \
  --work-root /PRIVATE/results/H50Z405_review_20261108 \
  --method s88-steerable \
  --s100-cross-review --s101-global-gap-ablation
```

Для 406/407 нужны новые отдельные рабочие каталоги. Файлы оригинальных BMP, веса и закрытые экспертные разметки **не загружать в публичный GitHub**. Сохранённые завершённые результаты нельзя перезаписывать новыми параметрами: используйте новый `--work-root` или корректный `--resume` с прежними параметрами.

После запуска нужны: `S95_ALL_OBJECTS/report.json`, `S95_ALL_OBJECTS/S95_all_classes_comparison.jpg`, `COMPACT_REAL_EVIDENCE/` (оригинальные пиксели для независимой слепой оценки), `S100_UNLABELED_X_CROSS_SHAPES/index.html` и `S101_GLOBAL_GAP_PATH_ABLATION/report.json`.

## Текущий критерий успеха

Оценивать не число выданных линий, а **полноту истинных видимых следов и количество ложных фрагментов** на независимых экспертных ROI тех же фотографий (S97–S99). Отдельно измерять точность основных морфологических классов, непрерывность кривых, ложные соединения и пропущенные завитки/короткие реальные следы. До этого результаты синтетических тестов подтверждают корректность программного конвейера, а не улучшение физического распознавания реальных H50Z.
