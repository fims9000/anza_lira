# S85 — обучаемый отбор дополнительных линий: исходный код и исследования

**ID:** `ANZA-LIRA-BC-S85-20261027`  
**Ветка:** `research/bubble-chamber-graph-lira`  
**Состояние:** `SOURCE_ONLY_VERIFIED / TRAIN_CAL_TEST_NOT_EXECUTED`  
**Дата:** 27.10.2026

## Что реализовано

- Вектор из 13 признаков кандидата: локальный контраст, градиент, длина, кривизна/прямолинейность, близость к исходным линиям и **контекст графовых контактов S56**.
- Регуляризованная логистическая регрессия с отдельными моделями по SOURCE-фото, учёт дисбаланса и группировка всех шумовых преобразований одной сцены.
- Метки для обучения создаются **только после слепого пиксельного обнаружения** на фрагментах из synthetic TRAIN: уверенно совпавшая истинная линия, уверенно совпавший искусственный decoy или уверенно отдалённый фоновый кандидат; сомнительные пересекающиеся случаи получают ABSTAIN.
- Два неизменяемых порога вероятности (`0.85`, `0.95`). Без достаточной независимой искусственной разметки модель не обучается и **не добавляет** линий.
- Полный код трёх последовательных фаз `TRAIN -> CAL -> TEST`: отдельные шаблоны visualMetro film070 TRAIN/CAL/TEST, непересекающиеся seed, приватные веса модели, сохранённые SHA-256, строгий критерий выбора по синтетическим **полным цепочкам и отсутствию роста неправильных стыков**, парный bootstrap на уровне всей сцены.
- Пиксельная проверка `scratch_grain`, детерминированная по отдельному noise seed и без знания синтетических координат.
- Отдельный read-only `native` аудит для 39 настоящих H50Z-участков; все машинные связи имеют статус **UNKNOWN**, автоматические физические соединения не разрешены.

## Что НЕ сделано и почему

В текущем исполняемом контейнере нет оригинальных приватных H50Z `005`/`006` 512×512-кропов и файлов visualMetro `1mH2Data/S1`. В GitHub этих файлов тоже нет (верно с точки зрения приватности). Следовательно, **не выполнено реальное обучение**, CAL/TEST на этих данных, native-аудит на 39 участках и не получено научных чисел по S85. Исторические результаты S84 не копируются и не называются S85. Факт прохождения unit-тестов не является свидетельством улучшения алгоритма.

Исходные H50Z `005`/`006` — две фотографии одного физического запуска. measured film070 **не** является разметкой физических треков H50Z. Даже после приватного запуска S85 получим только оценку переноса искусственных вставок, не физическую валидацию независимых событий.

## Как выполнить приватное исследование

Команды выполнять в корне исходного репозитория. TRAIN модель **никогда** не сохранять в публичную папку репозитория.

```bash
python scripts/research/bubble_chamber/s85_train_calibrate_test_learned.py train \
  --visualmetro /PRIVATE/1mH2Data/S1 \
  --photo-tiles /PRIVATE/tiles \
  --out /PRIVATE/S85_TRAIN_MODELS_PRIVATE.json \
  --public-train-receipt /PRIVATE/S85_PUBLIC_TRAIN_RECEIPT.json

python scripts/research/bubble_chamber/s85_train_calibrate_test_learned.py cal \
  --visualmetro /PRIVATE/1mH2Data/S1 \
  --photo-tiles /PRIVATE/tiles \
  --train-models /PRIVATE/S85_TRAIN_MODELS_PRIVATE.json \
  --out /PRIVATE/S85_FROZEN_CAL.json

python scripts/research/bubble_chamber/s85_train_calibrate_test_learned.py test \
  --visualmetro /PRIVATE/1mH2Data/S1 \
  --photo-tiles /PRIVATE/tiles \
  --train-models /PRIVATE/S85_TRAIN_MODELS_PRIVATE.json \
  --calibration /PRIVATE/S85_FROZEN_CAL.json \
  --out /PRIVATE/S85_FRESH_TEST.json

python scripts/research/bubble_chamber/s85_native_unknown_audit_v2.py \
  --visualmetro /PRIVATE/1mH2Data/S1 \
  --photo-tiles /PRIVATE/tiles \
  --train-models /PRIVATE/S85_TRAIN_MODELS_PRIVATE.json \
  --calibration /PRIVATE/S85_FROZEN_CAL.json \
  --out /PRIVATE/S85_NATIVE_UNKNOWN.json
```

Перед каждым этапом код проверяет SHA-256 своего протокола, неизменность предыдущего артефакта и сохранность базового S72. Все выходные файлы immutable (перезапись запрещена); повторяемость теста проверяется записью **в новый файл** и сравнением `sha256`.

## Что считать научным успехом

В соответствии с заранее замороженным протоколом, на SOURCE CAL при σ=1.1 должно быть хотя бы два дополнительных правильных синтетических стыка и два shape-сопоставленных истинных фрагмента, **без роста** остальных предложенных стыков; на чистых и `scratch_grain` сценах не должно быть больше остальных стыков и не должно уменьшиться число полных цепочек. Только после этого можно рассматривать новый отложенный TEST на противоположном фотофоне. Даже если CAL выбран не-baseline, это **не** даёт разрешения автоматически соединять настоящие физические треки H50Z.

## Ближайший исполнимый шаг

После подключения приватного архива изображений и visualMetro: запустить `TRAIN`, проверить число неамбивалентных истинных/отрицательных кандидатов в каждом SOURCE-направлении, заморозить веса и SHA-256, затем `CAL`, и только после этого впервые открыть `TEST`. Если TRAIN откажется из-за недостаточных меток — фиксируем отрицательный результат и возвращаемся к извлечению фрагментов, а не «дотягиваем» показатели порогами теста.
