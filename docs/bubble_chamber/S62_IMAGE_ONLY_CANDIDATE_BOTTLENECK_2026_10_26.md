# S62 — image-only извлечение кандидатов: граница применимости результатов S56–S60

**26 октября 2026 · `research/bubble-chamber-graph-lira` · 96 новых тестовых сцен · физически подтверждённых треков 0.**

## Зачем это нужно

В S56/S59/S60 геометрическая модель получала из симулятора уже заданные (хотя и зашумлённые) полилинии 7 искусственных фрагментов. Это **не означает**, что алгоритм извлечения может получить те же линии с настоящей фотографии. Задача S62 — измерить на контролируемых искусственных вставках, насколько много траекторий теряется до начала построения графа.

## Замороженный до теста протокол

`S62_FROZEN_IMAGE_ONLY_CANDIDATE_AUDIT_2026_10_26.md`.

- Данные: 145 операторски измеренных кадров visualMetro фильма 070. Геометрия искусственных траекторий берётся только из 36 кадров прежнего S37 TEST-фолда (79/30/36). Изображения-фоны — реальные H50Z `005` и `006` одного физического запуска.
- Новые seed тестовых сцен: 20266203/04 (005→006), 20266213/14 (006→005), по **24 сцены** на seed, всего **96**.
- В каждой сцене: 6 фрагментов двух искусственных треков + 1 искусственный обманный штрих. Итого **576** искусственных фрагментов, **96** обманных штрихов, **384** искусственно истинных стыка, **192** потенциальных целых искусственных трёхчастных пути.
- Детектор получает **только 192×192 пиксели**. Истинные относительно генератора полилинии находятся только в отдельной оценочной процедуре. Для двух потоков используются исходные S39 без обучения: локальная темнота, многомасштабный Hessian ridge, Sobel; маски имеют одинаковый бюджет 3.5% пикселей. В четвёртом сравнении полилинии реально выводятся из изображения посредством `extract_ridges`, без подсказки исходных координат.
- Для вычисления верхней границы на потенциально соединяемые искусственные фрагменты принята фиксированная **толерантность 2 пикселя** для масок и 4 пикселя для извлечённых полилиний. Нужны ≥40% покрытых точек и наблюдение обоих концов. Настоящих физических GT-полилиний в H50Z нет.

## Результаты S62: суммы по 96 тестовым сценам

| Оцениваемый источник изображения | Поддержано из 576 искусственных фрагментов | Условно доступны из 384 искусственных правильных стыков | Полных условно возможных путей из 192 | Поддержано из 96 искусственных обманных штрихов |
|---|---:|---:|---:|---:|
| Многомасштабный ridge | **297 (51.6%)** | 149 (38.8%) | 56 (29.2%) | 51 (53.1%) |
| Локальная темнота | **335 (58.2%)** | 170 (44.3%) | 64 (33.3%) | 62 (64.6%) |
| Sobel | **316 (54.9%)** | 163 (42.4%) | 64 (33.3%) | 50 (52.1%) |
| **Полилинии из пикселей (`extract_ridges`)** | **205 (35.6%)** | **73 (19.0%)** | **19 (9.9%)** | 23 (24.0%) |

**Вывод:** текущий способ извлечения полилиний с изображения покрывает слишком мало искусственных фрагментов, чтобы воспроизводить высокий уровень изолированной геометрической сборки S56. В задачи следующего исследования приоритетно входят *fragment discovery*, слабые/частично перекрывающиеся штрихи, управление пересечениями, восстановление прерванных низкоконтрастных кандидатов — ещё до обучения связи графа. Пороговые маски имеют существенно более высокую доступность, но пока не дают однозначные полилинии и одновременно поддерживают обманные штрихи.

**Ни одна цифра не является физической precision/recall:** фрагменты и обманные линии нарисованы искусственно, фон real, координаты оператора принадлежат другой плёнке; даже сравнение `extract_ridges` производится по *зашумлённым* координатам синтетического генератора, а не по вручную найденным физическим трекам. У фрагмента может быть высокая оптическая поддержка из-за совпадения с имеющейся фоновой линией, что не подтверждает происхождение.
