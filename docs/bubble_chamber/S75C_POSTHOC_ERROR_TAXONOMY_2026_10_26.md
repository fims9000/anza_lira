# S75C — ошибочные и неопределённые соединения после S69: ретроспективная структура

**26 октября 2026 · `ANZA-LIRA-BC-S75C-20261026` · исключительно ретроспективный анализ тех же 96 S75 TEST-сцен.** Не является новым независимым тестом и не содержит переобучения, новой настройки порогов или калибровки на TEST.

## Причина проверки

Исходный исправленный оценщик S69 различает три причины, по которым предложенный стык нельзя подтвердить относительно искусственно известных соседних фрагментов: (1) другая идентифицированная пара, (2) хотя бы одна не сопоставленная с искусственной линией полилиния, (3) выбран неправильный конец у двух сопоставленных полилиний. Сводные S75-отчёты объединяли эти причины в одном столбце; теперь категории подсчитаны по тем же неизменённым предсказаниям.

`S75C` **точно повторил** исходные агрегаты S75 для каждой из четырёх комбинаций seed, всех трёх фотометрических условий и всех трёх методов. Проверены SHA-256 исходного замороженного CAL и TEST, неизменность S72 scorer/метода и исправленного S69. Доступны только суммарные значения, фотографии и отдельные координаты не сохраняются в GitHub.

Без физической экспертной GT причины отдельных реальных следов неизвестны.

## Важное методологическое ограничение

Ноль зарегистрированных ошибок «неверный конец» **не доказывает точность локализации концов**. Этап `_candidate_associations` перед S69 уже **требует геометрической близости обоих концов полилинии** к известному искусственному фрагменту. Поэтому значительная часть предполагаемых ошибок концов отклоняется на стадии сопоставления и попадает в столбец «не удалось сопоставить», а не в столбец «неверный конец». Такой фильтр не даёт честно разложить ошибки на независимые классы по реальным фотографиям.

**Практический итог:** по действующим правилам проверки ограничивающее место — доступность отдельных сопоставляемых с искусственной линией полилиний, а не доказанная ошибка классификации физических узлов. Следующая научная проверка должна разъединить *криволинейное пространственное совпадение* и *точность конечных точек*, применяя endpoint-blind сопоставление как отдельный ретроспективный диагностический контроль, а не менять основную S69-метрику без новой валидации.

```bash
python scripts/research/bubble_chamber/s75_posthoc_error_taxonomy.py \
 --visualmetro /PRIVATE/1mH2Data/S1 --photo-tiles /PRIVATE/source_39_H50Z_crops \
```
