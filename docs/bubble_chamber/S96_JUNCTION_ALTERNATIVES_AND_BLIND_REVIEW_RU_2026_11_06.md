# S96 — проверяем продолжения после пересечения, не склеиваем физические треки вслепую

**Ветка:** \`feature/bubble-s96-junction-alternatives-2026-11-06\`. Подготовлена на основе S95 PR #11, далее цепочка S94 → S93 → S92 → \`research/bubble-chamber-graph-lira\`. Все исходные S86/S92/S95, BMP и операторские данные неизменны.

## 1. Что изменено в научной постановке

Распознавание \`TRACK / ARTIFACT / CROSS / BUNDLE / COILING / UNKNOWN\` в S95 описывает **тип наблюдаемого фрагмента**. Но даже четыре правильно найденных отрезка сами по себе не определяют, как проходит **одна траектория** через перекрестие. Это другая задача: **сопоставление продолжений** (2D instance association).

S67 пытался соединять ветви по касательным, S68 разрешал пересечение, сохраняя отдельные плечи. Результаты S67 на синтетическом TEST не доказали прироста правильных соединений. Поэтому S96 не подменяет базовый метод и не обещает физическую правильность; он делает **исчерпывающие и обратимые гипотезы** с причинами отказа, не расходуя скрытую проверочную выборку.

На входе S96 только выделенные S86/S87 линии и метаданные S95. Операторские трековые ID и физические GT для выбора не используются.

## 2. Геометрическое сравнение продолжений

Для конца каждого фрагмента известны конечная точка \`p\` и наружная касательная \`u\`. Концы, находящиеся в пределах локального радиуса \`12 px\`, объединяются в кандидаты на общий узел. Максимальный пространственный размах группы — \`18 px\`; связанные через длинную цепь соседств концы не принимаются за одну точку столкновения.

Для **ровно четырёх независимых плеч** оцениваются попарные противоположные касательные:

\`\`\`text
compatibility(A,B) = - u_A · u_B
score(A,B) = compatibility(A,B) - 0.015 * (distA + distB)/(2*12)
\`\`\`

Допускаются отклонения от прямого продолжения до \`35°\`, а лучший вариант должен выигрывать у альтернативы на каждом из двух концов минимум \`0.12\` по score. Два независимых соединения должны совместно охватывать **все четыре плеча**: пары \`AB+CD\`, \`AC+BD\` или \`AD+BC\`. Если геометрических оснований недостаточно, алгоритм **отказывается от парировки полностью**. Отдельно проверяются уникальность использования каждого конца и отсутствие циклов при построении предположительной цепочки.

**Три плеча:** \`THREE_ARM_BRANCH_ABSTAIN\`, не выбираем «самые прямые» два из трёх как заведомо одну частицу.

**Пять или больше плеч:** \`DENSE_BUNDLE_ABSTAIN\`. Задевшие друг друга в проекции линии и реальный пучок нельзя различить только по углам.

**Две части прямой с пробелом:** это не пересечение; оставляем на S92 (кривые Эрмита, конкурирующие связи). Нельзя смешивать две задачи.

Результат пары \`PROVISIONAL_2D_CROSSING_CONTINUATION\` означает только **гипотезу визуального продолжения**. Исходные фрагменты остаются в том же виде, а небольшой гипотетический участок возле центра хранится **отдельно**. Никакая автоматическая физическая склейка не разрешена.

## 3. Главное ограничение S96-v1

S96-v1 принимает **уже выделенные и разделённые фрагменты** S86/S87. Если S86 ранее слил всё пересечение в **один** компонент и его четыре плеча не существуют как отдельные линии, S96 не восстанавливает их из воздуха. Для этого нужен следующий, независимый от меток модуль pixel-junction splitting с обратимым отображением на исходные пиксели. Это честно записано в \`report.json\`.

Также S96 не находит совсем пропущенные первичным детектором линии и не устанавливает, является ли визуальное пересечение следствием взаимодействия частиц.

## 4. Запуск поверх существующего результата S95, без 207-МБ BMP

\`\`\`bash
git fetch origin
git switch feature/bubble-s96-junction-alternatives-2026-11-06
python -m pip install -r docs/bubble_chamber/requirements.txt

python scripts/research/bubble_chamber/physicists_s96_junctions.py run \
  --s86-dir /PRIVATE/results/H50Z_405_ALL_CLASSES/S93_SOURCES/S86 \
  --s95-dir /PRIVATE/results/H50Z_405_ALL_CLASSES/S95_ALL_OBJECTS \
  --private-out-dir /PRIVATE/results/H50Z_405_S96_METADATA
\`\`\`

Получатся \`junction_hypotheses.ndjson\`, \`visual_continuation_pairs_unknown.ndjson\`, \`visual_chain_hypotheses_unknown.ndjson\`, \`original_observed_component_inventory.ndjson\` и \`report.json\`, все с SHA исходных S86/S95. Метаданные сохраняют **все оригинальные объекты**, включая не сопоставленные линии и мусороподобные штрихи.

Без исходной фотографии эксперты **не могут законно присвоить результатам классы визуальной правильности**, потому что одних координат и модельного предположения недостаточно.

## 5. Запуск с настоящей фотографией и независимой разметкой

\`\`\`bash
python scripts/research/bubble_chamber/physicists_s96_junctions.py run \
  --s86-dir /PRIVATE/results/H50Z_405_ALL_CLASSES/S93_SOURCES/S86 \
  --s95-dir /PRIVATE/results/H50Z_405_ALL_CLASSES/S95_ALL_OBJECTS \
  --bmp /PRIVATE/H50Z/H50Z_030_01_405.bmp \
  --private-out-dir /PRIVATE/results/H50Z_405_S96_REVIEW \
  --preview-limit 32 --crop-size 320
\`\`\`

Теперь \`/PRIVATE/results/H50Z_405_S96_REVIEW/review/index.html\` показывает исходные 320px кропы **слева без изменений**, **справа с обозначением наблюдаемых концов A/B/C/D**. **Машинная парировка в интерфейсе скрыта**, чтобы эксперт не повторял автоматически решение алгоритма.

Человек выбирает класс формы \`CROSSING\`, \`THREE_ARM_BRANCH\`, \`BUNDLE_OR_OVERLAP\`, \`CALIBRATION_MARK_OR_ARTIFACT\`, \`UNDECIDABLE\`; для 4 независимых плеч отдельно: \`AB|CD\`, \`AC|BD\`, \`AD|BC\`, \`NONE\`, \`UNDECIDABLE\`.

Можно скачать \`S96_human_junction_review_PRIVATE.json\`, а затем импортировать этот JSON в ту же страницу и продолжить проверку. Файл связан с SHA исходной фотографии и отчёта конкретной версии S96.

После разметки:

\`\`\`bash
python scripts/research/bubble_chamber/physicists_s96_junctions.py compile \
  --review-pack /PRIVATE/results/H50Z_405_S96_REVIEW/review/review_pack.json \
  --human-review-json /PRIVATE/results/S96_human_junction_review_PRIVATE.json \
  --private-out-json /PRIVATE/results/H50Z_405_S96_HUMAN_SUMMARY.json
\`\`\`

Результат показывает число просмотренных узлов и **согласованность 2D парировок человека и модели только среди просмотренных, определённых, машиной парированных 4-лучевых случаев**. Не просмотренные, неразрешённые и отклонённые случаи не превращаются в доказанные отрицательные. Нельзя распространять это значение на оценку истинной идентичности частиц или на полную популяцию H50Z.

## 6. Экспериментальная проверка

CI: синтетический крест из четырёх раздельных плеч, Y-ветвление, 5-лучевой пучок, две части простой прямой, неверно направленные плечи, оборот полилиний, вращение, зеркальное отражение, плотная сцена и исправность fail-closed отказов. End-to-end: небольшой **искусственный** 8-битный BMP → S86 → S92 → S95 → S96 → оригинальные кропы → автономный экспертный HTML → SHA-bound результат. Это тест инженерного контракта, **не экспертная точность на реальной плёнке**.

**Остаётся:** (a) обратимо делить слитые пиксельные X/Y узлы на наблюдаемые плечи, (b) выполнить независимые экспертные визуальные проверки, (c) сравнить S39, S67/S68, S92, S96 по matched 2D трассам на одних и тех же экспериментах. Без физического сопоставления и оригинального фото результаты ограничиваются синтетическими проверками.
