# S94 — что реально можно улучшить по присланной разметке без большого BMP

**Ветка:** \`feature/bubble-s94-labels-guard-2026-11-06\` (поверх S93 PR #9, S92 PR #8). \`research/bubble-chamber-graph-lira\` и исходные фото/разметка не изменены.

## 1. Какие реальные метки у нас были

Прежняя проверка исходного \`H50Z_030_01_006.7z\` выявила небольшой \`labels.json\` (~348 КБ, SHA-256 \`df3fd9034d44ea4c27e79c50b5bc3c2de873071403740ab2c8d9f62004165ad7\`). По предыдущему аудиту там 105 H50Z фото и 1407 точек, включая 570 \`start\`, 837 служебных реперных отметок \`f1...f8\`. Метки \`start\` — **кандидатные точки начала/вершины**, \`f1–f8\` — **калибровочные реперы**. Это **не** пиксельные маски треков, **не** типы частиц, **не** размеченные «мусор/волос/спираль» и **не** достоверные пары соединяемых фрагментов.

Реальные архивы \`1mH2Data.7z\` и \`070_008.7z\` содержат также операторские *измеренные точки* 3D и соответствующих проекций visualMetro, относящиеся к другой системе координат/фильмам. Измеренная принадлежность точек треку полезна для геометрии, но на H50Z нельзя переносить эти координаты как готовую GT-разметку. Соответствие конкретной фотографии и visualMetro кадра нужно установить независимо.

**Ограничение данной среды:** здесь не удалось получить исходный \`labels.json\` отдельным файлом. Большие присланные ZIP/BMP не материализуются из-за лимита ~100 МБ. Поэтому утверждения о первоначальных 105 фото и 570 точках основаны на **историческом** аудите и не являются результатом повторной проверки S94. S94 проверен на синтетической JSON-фикстуре.

## 2. Что дописано

- **Проверка небольшой разметки вообще без фото.** \`physicists_s94_labels_audit.py\` открывает только JSON, проверяет исходное имя H50Z, ширину и высоту, допустимость \`start/f1..f8\`, числовые координаты, границы кадра, число точек и повторяющиеся номера реперов. Для повторяющегося \`f5\` **не выбирает произвольно один**: карантинирует обе конфликтующие отметки, сохраняя исходный файл неизменным.
- **Короткий трек около \`start\` не пропадает из главного вида.** S92 по геометрии мог посчитать его галочкой или волоском и убрать из основного отображения. S94 помечает близость к операторской точке и сохраняет короткий отрезок для просмотра \`NEAR_OPERATOR_START_MANUAL_REVIEW_NOT_GT\`. Это не означает, что \`start\` гарантирует наличие частицы.
- **Калибровочные кресты не превращаются в автоматические соединения.** Если любая часть предполагаемого моста проходит рядом с \`f1..f8\` (или один из его исходных фрагментов попадает в такую область), решение меняется на \`KEYPOINT_REGION_ABSTAIN_NOT_A_TRACK_JOIN\`. Отрисованная гипотеза может оставаться в журнале, но не выдаётся за подтверждённый физический трек.
- **Сохранены SHA и независимость результатов.** В S92/S93 журнале указывается SHA исходного \`labels.json\`. Возобновление S93 с изменённым JSON отклоняется. Для фотографий, которых вообще нет в файле разметки, S94 явно пишет \`NO_MATCHING_PHOTO_LABELS\` и не притворяется, что «рядом точно нет реперов».
- **S92/S93 теперь принимают \`--labels\`** как необязательный аргумент; запуск **без** меток продолжает работать по прежнему протоколу.

## 3. Команда только для labels.json, без любых BMP

\`\`\`bash
git fetch origin
git switch feature/bubble-s94-labels-guard-2026-11-06
python -m pip install -r docs/bubble_chamber/requirements.txt

python scripts/research/bubble_chamber/physicists_s94_labels_audit.py \
  --labels /PRIVATE/H50Z/labels.json \
  --private-out-json /PRIVATE/results/H50Z_labels_audit.json
\`\`\`

Результат: JSON-отчёт по количеству \`start\` и реперов, нарушениям формата и неоднозначным дублям; с SHA оригинала. Исходная разметка остаётся нетронутой. Если метка отсутствует, это не означает отсутствия трека или репера на фотографии.

## 4. Когда исходный BMP снова доступен

Запуск S93 с разметкой на оригинальном H50Z:

\`\`\`bash
python scripts/research/bubble_chamber/physicists_s93_one_command_preview.py \
  --bmp /PRIVATE/H50Z/H50Z_030_01_405.bmp \
  --labels /PRIVATE/H50Z/labels.json \
  --private-out-dir /PRIVATE/results/H50Z_405_S94 \
  --method s88-steerable --max-side 2048
\`\`\`

Если кадра 405 нет среди 105 имён внутри разметки, в отчёте будет **\`NO_MATCHING_PHOTO_LABELS\`**, а не выдуманные координаты. S88 — классический детектор, не обученная ANZA; для оригинальной AZUNet нужен отдельный обученный checkpoint.

## 5. Что требует новых действительно полезных меток

| Цель | Есть ли подходящая разметка? | Что валидировать |
|---|---|---|
| Не спутать калибровочные метки с треком | Частично да: \`f1..f8\` | Геометрические флаги и ошибочное скрытие соседних настоящих линий |
| Не потерять короткий след возле вершины | Частично да: \`start\` | Ручная проверка трека вокруг клика, не только присутствие точки |
| Отличить волосок/галочку от настоящей короткой частицы | **Нет достоверных классов** | \`TRACK / ARTIFACT / UNKNOWN\` на отдельной контрольной выборке |
| Соединить разрывы без ложных объединений | **Нет парной трековой GT для H50Z** | \`SAME / DIFFERENT / UNKNOWN\` на пары фрагментов |
| Полностью найти слабую 2D спираль | **Нет контуров** | Экспертная полилиния/центрлайн, в том числе через слабоконтрастные участки |
| Переход к 3D и нейтронному событию | Нет подтверждённой связи H50Z ↔ visualMetro | Исходные три проекции и калибровка одного события |

**Научная постановка:** измерять не количество «отрезков, найденных детектором», а (i) пропущенные экспертные треки, (ii) удалённые по ошибке настоящие короткие треки, (iii) ложные слияния, (iv) полноценность кривой/спирали. Пороги выбирать по CAL на отдельных физических съёмках; не считать части разных проекций независимыми событиями.

**Статус:** код S94 + защищённые вызовы S92/S93 + синтетические тесты добавлены. Реальную H50Z точность без оригинальных пикселей или экспертных track-labels заявлять нельзя.
