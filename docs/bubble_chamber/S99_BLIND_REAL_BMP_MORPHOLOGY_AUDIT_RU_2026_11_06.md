# S99 — независимая проверка «трек / завиток / репер / мусор / пересечение» на исходных кадрах H50Z

**Цель.** Не просто считать, сколько линий обнаружил S88/S86 и сколько из них S95 назвал «похожими на треки», а проверить, соответствует ли машинная категория **независимой оценке исходных пикселей**. S98 измеряет связность уже наблюдаемых фрагментов; S99 впервые оценивает ошибки **морфологической классификации** таких фрагментов по явно размеченным человеческим линиям.

**Ограничение:** это оценка видимой 2D-морфологии, не распознавание конкретной частицы, нейтронного столкновения, реальной 3D траектории или полного фона снимка. Все настоящие H50Z-фотографии остаются в приватном локальном каталоге, не добавляются в GitHub.

## 1. До просмотра машинной разметки — выбрать ROI по всему реальному BMP

Одна исходная фотография `H50Z_030_01_405.bmp` занимает более 200 МБ. Полный интерактивный просмотр всех исходных пикселей неудобен и создаёт риск выбирать «красивые» участки, где алгоритм уже хорошо работает.

S99 выбирает ровно 18 исходных непересекающихся клеток размером не более 512×512 px: по **две случайные клетки в каждой из девяти пространственных зон** изображения. Выбор детерминирован по заранее записанному `seed`, SHA-256 исходного кадра и координатам клетки. **Ни один S86/S95 результат, маска или оценка ошибки не участвует в выборе ROI.** Разные кадры получают разные выборки при том же seed.

```bash
git fetch origin
git switch feature/bubble-s99-blind-morphology-validation-2026-11-06

python scripts/research/bubble_chamber/physicists_s99_blind_morphology.py prepare \
  --bmp /PRIVATE/H50Z/H50Z_030_01_405.bmp \
  --seed 20261106 \
  --tile-size 512 --roi-count 18 \
  --strata-rows 3 --strata-cols 3 \
  --private-out-dir /PRIVATE/results/H50Z405_S99_BLIND_REFERENCE
```

Аналогично `406.bmp` и `407.bmp`, обязательно **в отдельных выходных папках**, даже с одним seed.

Появятся: `s99_blind_selection.json` (открытая воспроизводимая схема выборки), `reference_pack.json` (исходный SHA), `tiles/*.png` (точные исходные пиксели без потерь) и независимый браузерный редактор `index.html`.

Внимание: выбор по равновероятным *клеткам* с возможными неполными крайними областями не является строго равновероятным выбором всех пикселей. К тому же оператор размечает только обнаруженные им визуальные линии. Поэтому **массовые доли или доверительные интервалы по физическим трекам всей плёнки по этим 18 ROI вычислять нельзя.** Это сбалансированная географическая выборка для честного первичного аудита ошибок, а не доказательство научной превосходности.

## 2. Человек размечает исходные фото вслепую, не видя ответов S95

Откройте локальный `/PRIVATE/results/H50Z405_S99_BLIND_REFERENCE/index.html`.

По нескольким точкам вдоль видимой линии нужно записать **изображение** (не физическую частицу) как один из классов:

| Человеческая 2D оценка | Что видно |
|---|---|
| `TRACK_LIKE` | Протяжённая регулярная линия, похожая на трек |
| `COILING_TRACK_LIKE` | Заметное закручивание / спираль |
| `FIDUCIAL_CROSS` | Реперный / калибровочный крест |
| `ARTIFACT` | По экспертной визуальной оценке мусор, царапина, галочка |
| `CROSSING_OR_BUNDLE` | Пересечение / пучок без достоверного разделения |
| `UNKNOWN` | Недостаточно визуальных данных |

Дополнительно `CLEAR / UNCERTAIN`: сомнительные человеческие объекты должны **исключаться**, а не автоматически становиться фоном. Каждая линия имеет `stroke_id` и `visual_instance_id`. На сильных изгибах ставьте более частые точки: шаг **не более 32 исходных пикселей**. По завершении экспортируйте `S97_independent_human_trace_reference_PRIVATE.json`, сохраните его в приватной папке и **не меняйте после просмотра предсказаний**. Для воспроизведения сеанса редактор поддерживает импорт того же JSON.

Хорошая дополнительная проверка — независимая разметка точно тех же ROI вторым физиком, до просмотра результатов первого специалиста и модели. Оба экспертных файла должны сохраняться отдельно.

## 3. Сохранить фактические машинные S86→S92→S95 на том же исходном BMP

Если соответствующие каталоги уже есть, их можно **переиспользовать**. Проверки S99 сверят источник, все исходные маски S86 и SHA-256 цепочку S92/S95. Если промежуточные файлы не сохранились, повторите обработку:

```bash
python scripts/research/bubble_chamber/physicists_s95_all_classes.py \
  --bmp /PRIVATE/H50Z/H50Z_030_01_405.bmp \
  --method s88-steerable \
  --min-length-px 4 --min-component-area 2 \
  --max-fragments-per-tile 2048 \
  --private-out-dir /PRIVATE/results/H50Z405_S95_REAL_RUN
```

В этом случае основные исходные каталоги:

- `/PRIVATE/results/H50Z405_S95_REAL_RUN/S93_SOURCES/S86`;
- `/PRIVATE/results/H50Z405_S95_REAL_RUN/S93_SOURCES/S92`;
- `/PRIVATE/results/H50Z405_S95_REAL_RUN/S95_ALL_OBJECTS`.

**Не путайте S88 со специально обученной ANZA-LIRA.** S88 — классический фильтр исходной структуры линии. Для честного сравнения AZUNet нужен собственный *действительно обученный* checkpoint и отдельные исходные S86/S92/S95 каталоги. Простой второй запуск того же S88 под именем AZUNET не даёт сравнения разных методов.

## 4. Сравнить машинные классы с независимыми человеческими линиями

```bash
python scripts/research/bubble_chamber/physicists_s99_blind_morphology.py evaluate \
  --pack-dir /PRIVATE/results/H50Z405_S99_BLIND_REFERENCE \
  --reference-json /PRIVATE/results/S97_independent_human_trace_reference_PRIVATE.json \
  --candidate S88=/PRIVATE/results/H50Z405_S95_REAL_RUN/S93_SOURCES/S86 \
  --s92 S88=/PRIVATE/results/H50Z405_S95_REAL_RUN/S93_SOURCES/S92 \
  --s95 S88=/PRIVATE/results/H50Z405_S95_REAL_RUN/S95_ALL_OBJECTS \
  --radius-px 2 --max-preview-tiles 9 \
  --private-out-dir /PRIVATE/results/H50Z405_S99_MORPHOLOGY_EVALUATION
```

При наличии других моделей повторите по одному комплекту `--candidate`, `--s92`, `--s95` на **каждый** метод, указывая одинаковое имя.

Получится:

- `morphology_benchmark.json` — сколько исходных точек независимых линий **вообще найдено S86**; сколько источников S95 назвал «трек», «завиток», «мусор», «репер», «пучок» или «неизвестно»; где совпало с человеческой оценкой и где нет.
- `index.html` — галерея `original / machine morphology + independent human line` на полном исходном разрешении выбранных плиток.
- `posthoc_gallery_manifest.json` — SHA снимка, SHA сгенерированных изображений и гарантия, что галерея создана **после** независимой разметки.

## Научная интерпретация

**Два разных вида ошибок:**

1. **S86 не нашёл исходную человеческую линию** — её точки в пределах заданного допуска не покрыты наблюдаемыми исходными центрлиниями. Это ошибка *обнаружения*, а не ошибка морфологической классификации S95.
2. **S86 нашёл линию, но S95 отнёс её к неправильному морфологическому классу** — условное несовпадение **среди уже наблюдаемых и однозначно сопоставленных точек**. Пункты пересечения с конкурирующими исходными фрагментами не получают фиктивную метку: система отказывается от присвоения.

`human_vs_machine_S95_category_sample_confusion_not_global_confusion_matrix` — таблица, ограниченная **только явно размеченными CLEAR экспертными линиями**. Это **не** полная confusion matrix всех объектов изображения. Без исчерпывающей разметки фона нельзя корректно оценить полную precision, F1 и false-positive rate. Точки одного трека коррелируют, поэтому их нельзя считать независимыми наблюдениями для статистического теста.

Для публикации нужны несколько независимых кадров/событий, заранее отделённые серии для выбора гиперпараметров и для проверки. Файлы операторских измерений VisualMetro 070 нельзя автоматически считать GT именно H50Z 405/406/407 без явного совпадения идентификаторов/координат кадров.

**Состояние проверки кода:** синтетический CI подтверждает исполняемость, SHA-цепочку, восстановление исходных пикселей и граничные случаи. Настоящие H50Z-проценты появятся **только после выполнения** этой команды на приватных оригиналах и завершения человеческой разметки.
