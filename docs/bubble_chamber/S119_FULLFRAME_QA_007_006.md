# S119 — полнокадровая проверка пузырьковой камеры H50Z (11.11.2026)

## Статус

**Технический конвейер работает на двух исходных 8-битных BMP целиком, но выдача пока не пригодна для принятия физических решений без экспертного просмотра.**

Ветвь: `research/bubble-chamber-s117-long-gap-identity`, PR #22. S114 и S115 извлекают только наблюдаемую геометрию, S117 группирует фрагменты, S118 объединяет дубли на перекрывающихся плитках. S119 добавляет более консервативную проверку направления по двум пространственным масштабам. Сохранение исходных кривых обязательно.

## Контроль целого кадра

| Показатель | `007` (ручная разметка) | `006` (без разметки треков) |
|---|---:|---:|
| Размер BMP | 9103×26317 | 9268×25324 |
| Плиток 2000×2000 с перекрытием ≥250 | 90/90 | 90/90 |
| Экземпляров наблюдаемых кривых S115 | 6928 | 5332 |
| Локальных групп S117 после дополнительной проверки | 5479 | 4201 |
| Глобальных групп S118 после дополнительной проверки | 3466 | 2697 |
| Объединений дублированных кривых между плитками | 2013 | 1504 |
| Переведено из автогруппировки в экспертный просмотр | 17 | 7 |

Оба исходных BMP проверены по SHA-256, вся область `[0,width]×[0,height]` покрыта 6×15 плитками без дыр. В группах нет дублированных source-curve keys; соединительные интервалы **не** считаются наблюдаемыми пикселями. Важный нюанс: количество групп **не** есть число физических треков.

## Ручная проверка `007` — частичная и ретроспективная

В JSON: 78 записей класса `track` (74 содержат штрихи), 45 класса `trash` (44 содержат штрихи). Аннотация **не исчерпывает** все видимые треки, не содержит доказанной идентификации частиц, и не поступала в алгоритм распознавания.

Покрытие центральных точек ручных штрихов рядом с наблюдаемыми кривыми: **64.04% в пределах 5 px**, **69.7% в пределах 10 px**. Для помеченного `trash` даже в пределах 5 px — **78.92%**: это показывает проблему распознавания крестов/артефактов как линий. Такие величины не являются ни precision, ни recall, ни F1 распознавания физических треков.

В двух глобальных группах остались **противоречия с уверенно сопоставленными ручными ID**: `48/122` и `57/99`. Три локальных автоматически соединённых ребра дают конфликтующие ручные ID (два относятся к одной и той же области в перекрывающихся плитках). Эти соединения нужно передать физикам в очередь `same/different/uncertain`; не принимать их за доказанную физическую ошибку без независимой экспертизы, но и не утверждать, что они верны.

## Без ручных меток — кадр `006`

Это другой исходный кадр **того же набора H50Z**, а не независимый фильм другого эксперимента. В нем нет ручной разметки линий, следовательно, никаких точных GT-метрик не существует. Проверены только полнота обработки, SHA, согласованность групп, сохранение источника и визуально заметные дефекты: пропущенные слабые и спиральные дуги, короткие фрагменты, кресты.

## Вывод и критерии для физиков

1. На `007` решить для конфликтов `48/122`, `57/99` и 50 выбранных спорных связей — один ли это трек или разные частицы.
2. На `007` отметить ошибки обнаружения: спиральные витки, слабые длинные линии, кресты и следы от аппарата. Низкий порог яркости без контроля ложных срабатываний не годится.
3. На `006` независимо выбрать и проверить характерные области, не перенося целевые метки `007`.
4. До подтверждения нельзя рассчитывать число треков/частиц, кривизну или ионизацию как измеренный физический результат. Разделять `observed`, `inferred` и `human-verified`.

## Воспроизведение

Сначала установить `requirements_s118.txt`. Из корня репозитория:

```bash
PYTHONPATH=. OPENBLAS_NUM_THREADS=1 python -m pytest -q \
  tests/test_s114.py tests/test_s115.py \
  tests/test_s117_gap_identity.py tests/test_s117_runner.py \
  tests/test_s118_tile_stitch.py tests/test_s118_full_bmp.py

PYTHONPATH=. OPENBLAS_NUM_THREADS=1 python \
  scripts/research/bubble_chamber/run_s118_full_bmp.py \
  --bmp /PRIVATE/H50Z_030_01_007.bmp \
  --out /PRIVATE/S118_007 --tile-size 2000 --overlap 250
```

Запуск `007` на ходу разработки имел отдельный консервативный **post-hoc** S119 audit (только снятие автосвязей по дальним касательным, без изменения наблюдаемых точек). В исходном S117 этот же многомасштабный предохранитель уже внедрён для новых запусков. **Числа post-hoc выдачи выше не следует выдавать за отдельный свежий запуск всего S114.** При смене порогов, плиточной сетки или ручных решений полный audit повторяется.

Исходные изображения, исходные ручные аннотации и приватные визуализации **не публикуются в публичном GitHub**. Пакет проверки для физиков создается отдельно.
