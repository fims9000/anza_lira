# S90 — приватный слепой экспертный просмотр фрагментов пузырьковой камеры

**Дата:** 29 октября 2026. **Ветка:** `research/bubble-chamber-graph-lira`.

**Статус:** воспроизводимый инструмент для получения ограниченного экспертного заключения о *внешнем виде линий*; НЕ валидация физических треков, НЕ разметка плотных масок, НЕ автоматическая идентификация частиц. S72/S85 и исходные S86/S88/S89 файлы не изменяются.

## Зачем этот этап

S89 показал, что S88 даёт ложные кандидаты на искусственных царапинах и реперах; локальная стабильность под небольшими возмущениями не разделяет царапины и реальные треки. Отбрасывать все «нестабильные» линии нельзя: это резко уменьшало покрытие синтетических слабых кривых. Поэтому следующий полезный результат — сделать разбор нескольких *машинных* примеров физиками возможным без ручной сегментации всей фотографии.

S90 создаёт по готовым приватным результатам S86/S88 + S89 **слепую, непубликуемую галерею**: слева исходные пиксели BMP без масштабирования, справа ровно одна выделенная линия. Все случаи визуально оформлены одинаково; S89-флаги и машинная оценка видны только в отдельном приватном техническом файле, не в интерфейсе эксперта.

Это не гарантирует идеальное ослепление: эксперт может судить по самой форме линии. Отбор стратифицирован по S89-приоритетам, с лимитом на число фрагментов из каждого тайла и фиксированным хешированным порядком. Отбор **не использует** физических меток или результатов уже просмотренного TEST.

## Как получить пакет

На машине с настоящими приватными BMP **вне публичного GitHub** сначала выполните S86/S88 и S89, как указано в [S89 инструкции](S89_HARD_NEGATIVES_AND_PRIVATE_REVIEW_2026_10_29.md). Затем:

```bash
python scripts/research/bubble_chamber/physicists_s90_review.py build \
  --s86-dir /PRIVATE/results/H50Z_005_S86_S88 \
  --s89-dir /PRIVATE/results/H50Z_005_S89_AUDIT \
  --bmp /PRIVATE/H50Z/H50Z_030_01_005.bmp \
  --private-out-dir /PRIVATE/results/H50Z_005_S90_REVIEW \
  --max-cases 24 --max-per-tile 5 --crop-size 192
```

Создаётся закрытая папка (Unix `0700`, файлы `0600`):

- `index.html` — локальная галерея с оригиналом и подсветкой **одного** машинного фрагмента, тремя кнопками оценки, полем замечания и кнопкой экспорта JSON;
- `images/c_*_original.png`, `images/c_*_overlay.png` — настоящие исходные пиксели в нативном разрешении и версия с наложением; не отправлять в открытый репозиторий;
- `review_pack.json` — хеши исходного BMP, S86-манифеста, S89-аудита, изображений-превью, имена кандидатов и исходные координаты (приватные);
- `selection_private.json` — внутренние причины отбора, **не показывать** рецензенту, чтобы не подсказывать ответ.

Затем физик открывает **локально** `index.html` (без веб-сервера), проставляет оценки 1/2/3, указывает неперсональный `reviewer_id` вроде `physicist_01` и скачивает приватный JSON. Допустим неполный просмотр, но он явно учитывается в итоговом отчёте. При закрытии страницы несохранённые решения пропадают: браузерное хранилище не используется. Никаких запросов во внешние сервисы код не выполняет.

Смысл ответа: `TRACK_LIKE` — *визуально напоминает трек*, `ARTIFACT_LIKE` — *визуально напоминает дефект плёнки*, `UNDECIDABLE` — *не могу определить по данному 2D изображению*. Никакое значение не означает доказанную физическую идентичность, `dE/dx` или корректную связь частиц.

## Проверка ответов 1–2 и более рецензентов

```bash
python scripts/research/bubble_chamber/physicists_s90_review.py verify \
  --pack-dir /PRIVATE/results/H50Z_005_S90_REVIEW \
  --responses /PRIVATE/reviews/PRIVATE_S90_physicist_01_decisions.json \
              /PRIVATE/reviews/PRIVATE_S90_physicist_02_decisions.json \
  --private-out-dir /PRIVATE/results/H50Z_005_S90_VERIFIED
```

`review_summary.json` хранит количество независимых рецензентов, охват просмотра, число совпавших/противоречивых оценок. `case_votes.ndjson` содержит решения по каждому машинному фрагменту с его неизменным исходным ID. Все результаты **приватные**.

Проверка строго отклоняет: несовпадающий SHA-256 пакета, изменённое изображение-превью, чужой или повторный ID кандидата, неизвестный ответ, дублирующийся идентификатор рецензента, чрезмерный текст и попытку записи в исходный каталог. Она **не** записывает оценки в S86/89, не обучает сеть, не модифицирует исходную маску и не делает автоматических соединений.

Согласие даже двух рецензентов — ещё **не подтверждённая физическая истина**. Итог обозначает лишь `IMAGE_APPEARANCE_*_AGREEMENT_NOT_GT`. Чтобы публиковать метрики физической сегментации, понадобится отдельно согласованный экспертный протокол с независимыми физическими запусками, эталонной линией/объектом и закрытым TEST. Пользователю не требуется самостоятельно размечать изображения.

## Тестирование

Тесты `tests/test_s90_physicist_review.py` создают только сгенерированный grayscale BMP и прогоняют полный путь S86/S88 → S89 → S90 → проверка двух независимых ответов. Проверяются пиксельная идентичность исходных кропов, хеши, права доступа, инвариант неизменности масок, слепой интерфейс, повторный запуск, подмена ответов и согласие/расхождение двух рецензентов. GitHub Actions workflow использует только эти синтетические тесты и проверяет отсутствие приватных изображений или весов в исходниках.

**Ни в тестах, ни в публичном GitHub нет настоящих H50Z-фотографий, частных координат, моделей или заключений физиков.** Настоящий прогон S90 на H50Z возможен только там, где доступны оригинальные файлы S86/S89 и BMP; в текущем изолированном рабочем окружении их нет.
