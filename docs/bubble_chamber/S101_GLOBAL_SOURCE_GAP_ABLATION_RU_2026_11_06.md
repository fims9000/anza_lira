# S101: глобальное согласование разрывов треков вместо жадного выбора S92

**Научная задача.** ANZA-LIRA анализирует реальные фотографии пузырьковой камеры. После выделения линий S86/S87 постобработка S92 строит гипотезы того, какие короткие фрагменты могли принадлежать одной видимой 2D траектории. Исходный S92 выбирает кандидата с наибольшим локальным геометрическим score, после чего занятые концы больше не рассматриваются. В результате одна сильная, но неудачная перемычка может заблокировать две совместимые перемычки с лучшей суммарной оценкой.

**S101 — альтернативный метод выбора ИЗ ТОГО ЖЕ неизменного набора кандидатов S92**, а не новая сегментация или физическая классификация частиц. Он не создаёт «обнаруженные» пиксели на месте пропусков, не меняет S86/S87/S92/S95/S96, не переименовывает первоначальные component_id и не утверждает физическую связь между частицами.

## 1. Как выбираем соединения

У каждого исходного компонента S86 есть два конца (порты 0 и 1). Ввиду неопределённости двум визуальным линиям нельзя автоматически присвоить общую физическую частицу, но для первого **обратимого 2D предложения** рассматривается простая цепь без разветвления или цикла.

Глобальная задача на одном связном кластере:

```text
maximize    sum(geometry_score(edge) * selected(edge))

subject to  каждый исходный конец используется не более одного раза;
            цепь из исходных компонентов не содержит циклов;
            выбранный edge уже был геометрически предложен S92;
            все исходные S92 UNKNOWN/ambiguity/third-fragment-abstain сохранены.
```

- В небольшом кластере (не более 16 рёбер) проверяются допустимые варианты с ограничениями и выбирается **точный максимум** исходной суммы score. При равенстве выбирается детерминированный вариант по ID.
- При 17–400 рёбрах и не более 320 концов применяется **приближённое** максимальное паросочетание по концам с последующим удалением циклов. Это не объявляется глобально точным решением.
- Более плотный кластер **целиком отклоняется** по бюджету, а не обрезается до удобно найденных рёбер.
- Кандидаты S92, которым присвоен `AMBIGUOUS_PARTNER_ABSTAIN` или `THIRD_FRAGMENT_NEAR_GAP_ABSTAIN`, в новый набор **не включаются**. Новый solver не должен делать из неопределённого человека/соседнего следа подтверждённый мост.

Например, для условных рёбер A—B (0,90), A—C (0,80), B—D (0,80), где A—B конфликтует сразу с двумя другими: жадный S92 выбирает A—B, сумма 0,90. Глобальный вариант выбирает A—C и B—D с суммой 1,60. **Это пример улучшения геометрической целевой функции, а не доказательство, что два новых соединения физически правильны.**

## 2. Запуск на сохранённых оригинальных S86 и S92

```bash
git fetch origin
git switch feature/bubble-s101-global-gap-path-ablation-2026-11-06

python scripts/research/bubble_chamber/physicists_s101_global_gap_ablation.py \
  --s86-dir /PRIVATE/results/H50Z405/S93_SOURCES/S86 \
  --s92-dir /PRIVATE/results/H50Z405/S93_SOURCES/S92 \
  --private-out-dir /PRIVATE/results/H50Z405_S101_GLOBAL_GAP
```

Пути здесь — **примеры**, не подтверждение, что эти файлы уже существуют в текущем вычислительном окружении. Если настоящие S86/S92 не сохранились, сначала выполните их от оригинального BMP через CLI PR #17. Полные BMP, экспертные разметки и машинные маски не копируются в публичный GitHub.

S101 повторно проверяет исходные сохранённые S86 mask/fragment tiles и SHA-256 `manifest.json`, имя и SHA исходного BMP по S92 `report.json`, точное количество и статусы `gap_proposals_unknown.ndjson`. Плотные S92 запуски, уже отказавшиеся строить предложения по исчерпанию бюджета, не трактуются как «нет разрывов»: S101 тоже отказывается от их переинтерпретации.

Создаются два **новых приватных** файла:
- `global_gap_review_unknown.ndjson` — все исходные пары, их прежние решения S92 и новое решение S101 без изменения исходного файла;
- `report.json` — сравнение суммарных scores, числа выбранных пар, числа отказов, фактического режима решателя и списка замененных предложений.

### Через общий локальный запуск H50Z

Если S86/S92 ещё не созданы и оригинальный BMP доступен локально, можно запустить S101 вместе с уже подготовленным инструментом PR #17:

```bash
python scripts/research/bubble_chamber/physicists_real_h50z_reproduce.py run \
  --bmp /PRIVATE/H50Z/H50Z_030_01_405.bmp \
  --method s88-steerable \
  --work-root /PRIVATE/results/H50Z405_WITH_GLOBAL_GAPS \
  --s101-global-gap-ablation
```

Эта команда создаст обычные исходные S86/S92/S95(/S96), два отдельных ZIP с настоящими исходными пикселями и дополнительный приватный `S101_GLOBAL_GAP_PATH_ABLATION/report.json`. При повторном `--resume` завершённый S101 **не перезаписывается**: результат заново вычисляется в памяти и проверяется против неизменных оригинальных S86/S92 SHA и побайтного NDJSON. Если исходные S92 отказались строить предложения по лимиту плотности, дополнительный S101 также откажется, не маскируя эту проблему.

## 3. Сравнение по независимой операторской разметке

Если есть готовый независимый S97 `reference_pack.json` и операторский JSON **точно того же BMP**, в команду можно добавить:

```bash
  --s97-pack-dir /PRIVATE/results/H50Z405_S97_BLIND \
  --s97-human-reference /PRIVATE/results/H50Z405_S97_HUMAN.json
```

Тогда S98 **сначала по исходным человеческим линиям** выявляет соседние обнаруженные фрагменты, которые стоило бы визуально связать, а S101 отдельно сравнивает, сколько таких границ покрывает старое жадное решение и новый глобальный вариант. В отчёте остаются исходные SHA разметки, координаты и количество оцениваемых границ.

Размеченные человеком линии — это **наблюдаемая 2D морфология**, а не идентификатор реальной частицы. Поэтому сравнение по S98 является *условной оценкой соседств уже обнаруженных фрагментов*, а не recall всех физических треков и не precision по всему BMP. Результат на одной фотографии не имеет независимой event-level оценки статистической значимости.

## 4. Контроль безопасности

1. Каждый выбранный конец S86 принадлежит не более чем одному новому ребру.
2. Из выбранных рёбер нельзя сформировать цикл исходных component_id.
3. Конфликтующие по геометрии/третьей линии S92 abstention остаются отклонёнными.
4. `geometry_score` — инженерная оценка, **не вероятность физической идентичности**. Лучший суммарный score без независимой разметки не может служить показателем улучшения распознавания.
5. Если группа превышает бюджет точного/приближённого метода, отчёт явно отражает отказ, а не выдаёт нулевой результат за идеальную связность.
6. Ни одно соединение не добавляется в исходные пиксели/операторские маски.

**Нужный следующий научный эксперимент:** выполнить S86/S92/S101 на настоящих кадрах 405/406/407, затем оценить целостность на независимых S97/S98 визуально размеченных треках из *этих же снимков*. До этого S101 улучшает только постановку и оптимизацию гипотез, а не подтверждённую физическую точность ANZA-LIRA.
