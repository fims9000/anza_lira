# S11 — улучшение ANZA для восстановления тонких треков пузырьковых камер

Исследовательская ветка: `research/bubble-chamber-graph-lira`. Существующие исходные `models/azconv.py` и `models/segmentation.py` **не изменяются**. Цель — проверить, может ли учёт связности треков и согласование направлений в оригинальном AZConv улучшить результат по сравнению с сильной обычной U-Net.

## Нулевая гипотеза и предыстория

В S10 исходная AZUNet **не показала** устойчивого выигрыша над U-Net на изображениях, *синтезированных* из геометрии ручной разметки. Тест разделён по 25 кадрам одного фильма и не подтверждает перенос на другие плёнки или пропан. Простое повышение веса BCE для тонких линий ещё не решает разрывы и ложные слияния.

## Изменяемая часть

С11 использует оригинальные `AZUNet`, `AZConv2d` и встроенную модельную функцию `axis_alignment_loss`. Мы добавляем **только** совместимый тренировочный критерий, не подменяя ядро иной нейросетью:

\[
  L = L_{\mathrm{BCE+Dice}} + \lambda_{\mathrm{cl}}(1-\mathrm{soft\,clDice})
       + \lambda_{\mathrm{axis}}\,L_{\mathrm{AZ\,axis}}.
\]

- `soft clDice`: дифференцируемый мягкий скелет, штраф за потерю продолжения линии и лишние участки скелета; применяется **к U-Net и к ANZA** при одинаковом коэффициенте `0.20`.
- `AZ axis`: оригинальная функция для сравнения развернутого локального направления анизотропной свёртки с ориентировкой контрольного скелета (знак направления несущественен); коэффициент `0.05`; только у ANZA.
- Истинные пиксельные маски в текущем эксперименте искусственно сгенерированы по измеренным координатам. Использовать эту цель на H50Z, где есть только редкие подтверждённые точки, **нельзя**: немаркированный фон не является подтверждённым отрицательным классом.

## Предварительно зафиксированные абляции

| Arm | Исходная сеть | BCE+Dice | clDice | Согласование осей AZ |
|---|---|---|---|---|
| `unet_base` | BaselineUNet | да | нет | нет |
| `unet_cldice` | BaselineUNet | да | 0.20 | нет |
| `az_base` | AZUNet | да | нет | нет |
| `az_cldice` | AZUNet | да | 0.20 | нет |
| `az_cldice_axis` | AZUNet | да | 0.20 | 0.05 |

Каждый вариант переинициализируется при том же фиксированном модельном seed, получает те же изображения и мини-батчи, одинаковую деградацию контраста/шума. Кадры и изображения определяет отдельный `data_seed=20261024`, а модельные seed — `20261024/25/26`. Стандартные пороги бинаризации определяются **только по валидации**; анализ теста не используется для подбора весов или границ.

### Основные показатели

1. Dice, precision, recall на контрольной маске; обычный и сильный искусственный шум.
2. `hard clDice` — непрерывность скелета; макроусреднение по изображениям.
3. Парные доверительные интервалы по **исходным кадрам**, не по отдельным пикселям; результат отдельного seed сам по себе не доказывает воспроизводимость.
4. Время и число параметров, отслеживаемые S7; сохранённые оригинальные веса `best_final.pt`.
5. Отдельно требуется проверить частоту **ложных соединений разных частиц** после появления инстансной разметки. Один foreground mask и обычный clDice этого не позволяют.

## Конкретные критерии улучшения

- ANZA + topology должна выиграть в `hard clDice` и не ухудшить чистый Dice относительно **обеих** обычных U-Net при фиксированных кадрах и трёх инициализациях.
- Условная «победа» на одной случайной инициализации не принимается за подтверждение гипотезы.
- Для перехода к физической реконструкции потребуются реальные изображения, ручные полные/частичные контрольные контуры, калибровка стереопроекций и реперных крестов, затем проверка кривизны/остатков аппроксимации и исключение ложных объединений.

## Как воспроизводить

Из корня полного репозитория:

```bash
pytest -q tests/test_s11_axial_topology.py tests/test_s11_runner.py
python scripts/research/bubble_chamber/s11_train_axial_topology.py \
  --source procedural --out-dir results/s11_procedural_seed24 \
  --seed 20261024 --data-seed 20261024 --epochs 6 --size 64 \
  --train-limit 96 --val-limit 26 --test-limit 25 \
  --widths 4 6 8 12 --rules 2 --batch-size 8
```

Для настоящих измеренных координат film 070, с **синтетическими**, а не реальными пикселями:

```bash
python scripts/research/bubble_chamber/s11_train_axial_topology.py \
  --source visualmetro --measurements /private/1mH2Data/S1 \
  --out-dir results/s11_measured_geometry_seed24 \
  --seed 20261024 --data-seed 20261024 --epochs 8 --size 64 \
  --train-limit 120 --val-limit 26 --test-limit 25 \
  --widths 4 6 8 12 --rules 2 --batch-size 4
```

Исходный архив, реальные BMP и операционные метки в GitHub не включаются. Отсутствие реальной инстансной пиксельной разметки остаётся главным ограничением физического вывода.
