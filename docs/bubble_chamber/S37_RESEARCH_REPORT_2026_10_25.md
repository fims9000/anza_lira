# S37 — безопасность соединения фрагментов ANZA / Graph-LIRA (25.10.2026)

**Статус:** эксперимент полностью выполнен в локальном рабочем дереве `research/bubble-chamber-graph-lira`. Новые данные не являются независимой физической валидацией: это искусственно нанесённые линии/царапины и искусственно закрытые разрывы на **настоящем фотографическом фоне двух H50Z BMP одного запуска**. Нет экспертных эталонных масок настоящих линий/истинных отношений между фрагментами. **Автоматическое соединение реальных физических треков запрещено.**

## Исследовательская постановка

Цель: определить, помогает ли исходная ANZA (`AZUNet`/`AZConv2d`, оригинальный Git blob источника) в ранжировании **кандидатных стыков для человека** по сравнению с геометрией, фотометрией и исходной U-Net, а также проверить риск ложных соединений **на уровне целой сцены**. Эксперимент зарегистрирован до чтения новых тестовых вставок: `S37_PREDECLARED_PROTOCOL_2026_10_25.md`.

Материалы: проверенные контрольными суммами `1mH2Data.7z`, `H50Z_030_01_006.7z`, `070_008.7z`. Во 2D/3D измерениях visualMetro обнаружено **145 полных кадров, 1073 трека, 17321 3D-отметка, 51963 проекционные отметки**, без регистрации исходных кадров 070 на H50Z. Архив H50Z даёт 2 большие BMP и метаданные `labels.json` для 105 фото, но только 2 BMP физически присутствуют в исходном архиве. Все 39 источников 512×512 произведены из этих двух BMP. Полноценного экспертного GT треков в этих 39 кропах нет.

### Устранение источниковой ошибки S35

Старый приватный S35 использовал 144 вместо 145 пригодных исходных кадров. Выявлен конкретно отсутствующий `070_309`. Реплей S35 воспроизвёл исходные AUROC/число правильных и ложных связей при восстановлении **того же** набора из 144, что устраняет ложное подозрение о новом изменении алгоритма. В S37 используются все 145 с новым зафиксированным разбиением **79 train / 30 calibration / 36 test**, раздельным по оригинальному frame ID.

## Протокол S37

- Фотография 005 для синтетического обучения и калибровки, 006 для искусственного теста; затем обратное направление 006→005. **Обе BMP из одного физического запуска**, не независимые среды.
- Истинные только внутри симулятора пары: 2 правильно созданных + 4 неправильно созданных кандидатных связи в каждой сцене. На каждое направление 160 сцен обучения + 450 калибровки + 2×80 новых тестовых сцен; всего в тестах 320 сцен, 640 искусственно положительных и 1280 искусственно отрицательных пар.
- 7 одинаково обучаемых вариантов: расстояние, геометрия, геометрия+исходная фотометрия, геометрия+локальная, геометрия+AZUNet, геометрия+U-Net, геометрия+обе модели. При этом AZUNet S33 обучена на квантильно нормализованном входе, U-Net — на локально нормализованном; оба чекпойнта от одной и той же **только машинной** слабой разметки S31 и одинаковой исходной фотографии. **Архитектуры и веса не модифицированы.**
- На всех моделях одинаковые признаки геометрии/фотометрии в соответствующих вариантах, одинаковая логистическая регрессия для отношения пар. Часть нейросетевой карты вне двух проверенных окон — нейтральная (0.5), не метка физического фона.
- Сравнение прежнего эмпирического ограничения FPR≤0.02 по отдельным парам со строгим ограничением на событие `хотя бы одно ложное предложение в сцене`. Для последнего — 13 порогов только по train; односторонняя точная Clopper–Pearson с разделением family-wise alpha=.05 на **13×7×2=182** проверки. Порог выбирается только по calibration; если соответствующего нет, все стыки получают `ABSTAIN`.
- Цель 2% относится только к математическому эксперименту с сгенерированными относительно iid сценами, а не к возможной частоте физических ошибок. Конечные H50Z-фоны повторяются и существуют сильные сдвиги при переносе между снимками.

## Итоговая сравнительная таблица

AUROC — ранжирование искусственно созданных пар. `TP/FP` — число **предложенных человеку для проверки** верных/неверных соединений среди искусственной истины. Количество истинных пар: **320 на направление** (160 сцен × 2). Учитываются только решения после взаимного выбора пары и порога с возможностью отказа. Ни одна из записей не является физически подтверждённым соединением.

| Метод | AUROC 005→006 | AUROC 006→005 | Эмпирич. TP/FP 005→006 | Эмпирич. TP/FP 006→005 | Строгий TP/FP 005→006 | Строгий TP/FP 006→005 |
|---|---:|---:|---:|---:|---:|---:|
| distance | 0.6305 | 0.6372 | 9/7 | 6/7 | 0/0 | 0/0 |
| geometry | 0.8344 | 0.8335 | 16/1 | 29/3 | 1/1 | 2/0 |
| geometry+raw | 0.8420 | 0.8423 | 20/2 | 30/4 | 0/0 | 2/0 |
| geometry+local | 0.8404 | 0.8425 | 16/2 | 29/4 | 0/0 | 2/0 |
| geometry+AZUNet | 0.8395 | 0.8447 | 15/1 | 33/5 | 0/0 | 2/0 |
| geometry+UNet | 0.8394 | 0.8465 | 18/4 | 41/4 | 0/1 | 1/0 |
| geometry+both | 0.8395 | 0.8477 | 16/2 | 41/5 | 0/0 | 1/0 |

По AUROC **005→006 лидирует обычная геометрия+фотометрия (0.8420)**, **006→005 — совместная ANZA+U-Net (0.8477)**. Сравнение на четырёх синтетических seed-наборах не позволяет заключить об устойчивом превосходстве ANZA на настоящих фотографиях.

Под прежней эмпирической калибровкой `geometry+raw`: 005→006 **20 правильных / 2 ошибочных**, 006→005 **30 правильных / 4 ошибочных**; `geometry+AZUNet`: соответственно **15/1** и **33/5**. То есть выигрыш по AUROC не обязательно даёт более безопасное соединение после порогов.

При консервативном отборе по риску *сцены* калибровочные данные имеют ноль ошибочных предложений у выбранных порогов; односторонняя скорректированная верхняя граница при 0/450 — **0.01806 на независимой синтетической сцене**, условно на этой модели генерации. Реальные тесты показали **одно ошибочное предложение из 160 сцен** для геометрии и отдельно для U-Net в прямом направлении, несмотря на ноль ошибок в калибровке. В большинстве других вариантов строгий отбор почти полностью отказывается от соединений (настоящая симулированная полнота падает до 0–2 правильных предложений на 320 истинных связей каждого направления). **Это практический отрицательный результат для автономной эксплуатации**, а не гарантия безопасного режима.

Даже на искусственных тестовых сценах наблюдение 0 ложных сцен на 160 даёт обычную *без множественной поправки* одностороннюю 95%-ю верхнюю границу около **1.85%**, а одна ошибка — около **2.93%**. Они не экстраполируются на независимый физический запуск, поле, камеру или новый тип трека. Отдельные числа тестовых seed-наборов и полные агрегированные результаты представлены в JSON и не скрыты.

## Новый рабочий инструмент получения настоящей разметки

Собран **приватный автономный HTML-разметчик S37** (отдельный `S37_PRIVATE_OFFLINE_REVIEWER.zip`; НЕ часть публичного исходного пакета). Содержит все **39 исходных** 512×512 кропов (контроль пикселей SHA-256), **133 машинных кандидата линий** и **28 вопросов о связи**. Позволяет локально отмечать `same / different / unsure` и `accept / reject / unsure`, выбирать следующую непроверенную пару, сохранять ответы в S31-совместимый JSON, затем импортировать его обратно.

Выполнено 39/39 совпадений декодированных байтов пикселей; 30/39 исходных закодированных PNG-байтов совпадают, остальные 9 без потерь были переупакованы. JSON-экспорт→импорт и клавиатурная навигация проверены в изолированном браузерном тесте без доступа к сети. **Показ фотографий по локальному file:// в тестовой среде заблокирован политикой браузера**, поэтому полного ручного визуального приёмочного тестирования рендера оригинальных BMP здесь не утверждаем. HTML указывает на реальные PNG по относительным путям внутри распакованного ZIP.

Добавлен валидатор корректировок, который проверяет идентификаторы фрагментов, проекции, статусы, конечность координат, неизменность source SHA и то, что `UNKNOWN` не превратился автоматически в отрицательный класс. По результату записывает **только агрегированные счётчики** без приватных координат; **не присваивает статус физического эталона**.

Инструкция: `docs/bubble_chamber/S37_REVIEWER_HOWTO.md`. Пример:

```bash
python scripts/research/bubble_chamber/s37_validate_local_corrections.py \
  --private-source-zip /private/S35_ANZA_FRAGMENT_LINK_RESEARCH_PRIVATE.zip \
  --corrections /private/S31_machine_labels_local_corrections.json \
  --aggregate-report /private/S37_REVIEW_COUNTS.json
```

## Что защищено, что ещё не сделано

- **Готово:** контрольные суммы, точный S35-replay, новая S37 source-disjoint тестовая выборка, 7 сопоставимых методов, двунаправленный перенос по фотографиям, строгий контроль ложных соединений по сцене, базовый отказ (abstain), частичный приватный экспертный интерфейс и валидатор экспортов, исходные source-lock и тесты.
- **Не готово:** экспертные подписи настоящих 2D-масок/идентичности треков; независимые физические запуски/заливки и сопряжённые оригинальные 3-view BMP с калибровкой. Поэтому реальный pixel-Dice, настоящую track recall, фактические false merges per real track или PID измерить не удалось. Для новой серии нужно документировать `run_id`, `film_id`, `camera_id`, `calibration`, B-field, разрешения на использование данных и независимое физическое подтверждение.
- **Операционное решение:** `ABSTAIN` по умолчанию для физических соединений. Применять результаты ANZA только для **очередности ручной проверки гипотез**, не для автоматического восстановления события.

**Privacy:** публичный GitHub `fims9000/anza_lira` может содержать только код, тесты и агрегированные результаты; H50Z BMP/PNG/7z, визуальные координаты, HTML с реальными фото и веса нейросетей остаются приватно. Локальные эксперименты выполнены на рабочей ветке `research/bubble-chamber-graph-lira`; до отдельного подтверждённого пуша не выдавать это за опубликованные изменения на GitHub.
