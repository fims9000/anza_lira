# S97 — независимый 2D эталон видимых треков и честное сравнение детекторов

**Ветка:** \`feature/bubble-s97-independent-reference-benchmark-2026-11-06\` (основана на S96 PR #12 → S95 PR #11 → S94/S93/S92). Основная пузырьковая ветка, оригинальные BMP и приватные human-labels не изменяются.

## Почему нужна именно эта проверка

ANZA-LIRA может выделять **очень много** тёмных пиксельных линий и грамотно упорядочивать фрагменты, но это **не доказывает**, что модель нашла значимую часть реальных треков. Проверка только пар, которые модель сама предложила соединить, не замечает пропущенные слабые треки, короткие истинные следы и целые отсутствующие завитки.

В S97 эксперт **сначала размечает исходное фото без машинного оверлея**. После сохранения независимой разметки S86/S88/AZUNet или другие детекторы сравниваются на одних и тех же положительных человеческих линиях. Система отдельно показывает пропущенные участки вдоль них. Возможные мосты S92 и S96 **не считаются реально обнаруженными пикселями**.

### Что именно помечает физик

- \`TRACK_LIKE\` — заметная регулярная траектория;
- \`COILING_TRACK_LIKE\` — заметная закрученная траектория, спираль, дуга после возможного отклонения; **причина неизвестна**;
- \`FIDUCIAL_CROSS\` — калибровочный крест/репер;
- \`ARTIFACT\` — визуально мусорная галочка, царапина, волосок;
- \`CROSSING_OR_BUNDLE\` — пересечение/пучок с неоднозначной принадлежностью;
- \`UNKNOWN\` — невозможно надёжно определить.

Каждая нарисованная человеком линия получает собственный \`visual_instance_id\`. Если по одной фотографии видно несколько прерывистых фрагментов **одной визуальной линии**, можно использовать один ID, но это не подтверждает одну физическую частицу. Каждая отдельная нарисованная полилиния имеет собственный \`stroke_id\`. Эксперт выбирает \`CLEAR\` или \`UNCERTAIN\`.

**Метрика полного покрытия рассчитывается ТОЛЬКО на полилиниях \`TRACK_LIKE\` и \`COILING_TRACK_LIKE\` с \`CLEAR\`.** Артефакты, реперы, пучки, неизвестные и сомнительные линии в знаменатель положительного охвата не входят. Их наличие в частичной разметке не означает, что все остальные пиксели — фон.

## 1. Подготовить исходные пиксели, не загружая 200-МБ BMP в память целиком

\`\`\`bash
git fetch origin
git switch feature/bubble-s97-independent-reference-benchmark-2026-11-06
python -m pip install -r docs/bubble_chamber/requirements.txt

python scripts/research/bubble_chamber/physicists_s97_reference_benchmark.py prepare \
  --bmp /PRIVATE/H50Z/H50Z_030_01_405.bmp \
  --roi 1000 1000 2000 2000 \
  --private-out-dir /PRIVATE/results/H50Z_405_S97_EXPERT_REFERENCE \
  --tile-size 512 --max-tiles 256
\`\`\`

**Важно:** прямоугольник \`--roi 1000 1000 2000 2000\` — только ПРИМЕР синтаксиса. Реальные координаты нужно выбирать внутри конкретного исходного фото. Можно указать несколько \`--roi\`. При небольшом BMP (до 1 048 576 пикселей) \`--roi\` можно пропустить; для больших фото нужно явно указать области или \`--whole-photo\` с достаточным \`--max-tiles\`.

Создаются **PNG без потерь в полном оригинальном разрешении** в папке \`tiles/\`, \`reference_pack.json\`, краткий навигационный \`overview_navigation_only.jpg\` и автономная \`index.html\`. В отличие от downscaled обзорного JPEG отдельные плитки сохраняют все исходные значения серого. Каждый набор привязан к SHA-256 исходного BMP, исходным размерам и конкретным ROI; входные файлы не меняются.

## 2. Независимый физик размечает линии по исходной фотографии

Откройте локальный \`H50Z_405_S97_EXPERT_REFERENCE/index.html\` в браузере.

1. Выберите плитку оригинального фото.
2. Укажите новый ID визуальной линии, например \`T001\`.
3. Выберите один из шести классов и уверенность \`CLEAR / UNCERTAIN\`.
4. Щелчками пройдите через видимую линию в истинных координатах кадра. **Между точками не больше 32 исходных пикселей**; на изгибах ставьте их чаще. На разных плитках одной визуальной линии используйте тот же ID.
5. Сохраните линию; повторите для треков, коротких галочек, реперов, спиралей и неразрешённых областей. В конце скачайте \`S97_independent_human_trace_reference_PRIVATE.json\`.
6. Для возвращения к работе откройте ту же \`index.html\` и импортируйте сохранённый JSON.

Никакие машинные сегменты, предложенные мосты или физическая модель на странице **не показываются**. Неразмеченные области не становятся негативными примерами. Просмотр человеком только части плиток также не доказывает, что они размечены исчерпывающе.

## 3. Честно сравнить два метода на ОДНОЙ независимой разметке

\`\`\`bash
python scripts/research/bubble_chamber/physicists_s97_reference_benchmark.py evaluate \
  --pack-dir /PRIVATE/results/H50Z_405_S97_EXPERT_REFERENCE \
  --reference-json /PRIVATE/results/S97_independent_human_trace_reference_PRIVATE.json \
  --candidate S88=/PRIVATE/results/H50Z_405_S88_S86 \
  --candidate AZUNET=/PRIVATE/results/H50Z_405_AZUNET_S86 \
  --radius-px 2 \
  --private-out-json /PRIVATE/results/H50Z_405_S97_MATCHED_COVERAGE.json
\`\`\`

Названия \`S88\` и \`AZUNET\` здесь обозначают **конкретные реально сохранённые S86-прогоны**. Код проверяет SHA и исходные размеры фото, читает все исходные центрлинии и оценивает обнаружение в одном и том же радиусе 2 px от нарисованных экспертом точек. Если модели ещё не запускались, пути выше — просто шаблон, а не реальные артефакты.

Отчёт содержит:

- \`observed_positive_centerline_coverage\`: доля точек явно размеченных и уверенных настоящих визуальных линий, в радиусе 2 px от **наблюдённых S86 центрлиний**;
- результат **по каждой человеческой линии**;
- \`max_uncovered_span_px\` и число непокрытых участков длиной от 4 px — показывает, где трек действительно прерывается, даже если модель нашла его в целом;
- сколько тайлов S86 пропустил из-за ограничений на плотность/бюджет;
- парную **описательную** разницу S88 относительно AZUNet в процентных пунктах на одинаковой выборке.

Это **не pixel Dice, не precision, не F1, не доля всех обнаруженных физических треков на кадре**. Без полной независимой негативной маски эти метрики нельзя вычислить корректно. Один кадр или много плиток с одного кадра не дают доверительный интервал по независимым физическим событиям.

## 4. Проверить, не соединяет ли алгоритм две разные человеческие линии

Если для **первого** \`--candidate\` уже сохранены S92 и S96, к той же команде \`evaluate\` можно добавить:

\`\`\`bash
  --s92-dir /PRIVATE/results/H50Z_405_S92 \
  --s96-dir /PRIVATE/results/H50Z_405_S96
\`\`\`

Код сопоставит фрагменты **первого S86-прогона** с независимыми ручными линиями \`visual_instance_id\`. Слияние двух фрагментов, уверенно отнесённых человеком к двум разным визуальным ID, маркируется \`CONTRADICTS_ANNOTATED_VISUAL_INSTANCES\`. Согласующееся объединение — \`CONSISTENT_WITH_ANNOTATED_VISUAL_INSTANCE\`. Если хотя бы один источник частично/сомнительно размечен или проходит через пересечение, от оценки отказываемся. **Никакое машинное предложение не становится автоматически физически правильным.**

Эта доля противоречий определяется *только среди оценимых кандидатов, предложенных алгоритмом*. Она не показывает полный recall всех не предложенных связей. В дальнейшем для истинной оценки recall связей нужен отдельный дизайн выборки, в котором эксперт предъявляет положительные пары независимо от набора модельных предложений.

## 5. Как превратить это в нормальный исследовательский эксперимент

1. Подобрать **несколько независимых кадров и событий** (желательно разбить по плёнкам/сериям) и заранее отделить подбор параметров от проверки. Нельзя считать близкие плитки одного кадра независимыми объектами.
2. Дать минимум двум специалистам разметить одни и те же исходные ROI **независимо**. Измерить их согласованность; расхождения не исправлять автоматически голосованием машины.
3. Зафиксировать модели, пороги и критерии до проверки на отложенных кадрах; не выбирать параметры по результатам теста.
4. Сравнивать не только итоговый охват, но отдельно **короткие положительные следы, завитки, пропущенные участки и пересечения**. На поднаборе без полного фонового GT не публиковать accuracy/F1/precision.
5. Для оценки полного event-level физического восстановления потребуются **родные операторские идентификаторы треков и соответствующие кадры**. Измерения VisualMetro film-070 нельзя автоматически трактовать как GT снимка H50Z 405.

S97 пока прошёл только **синтетические программные проверки**. Ни одна цифра качества распознавания настоящего H50Z не утверждается до выполнения этого независимого эксперимента.
