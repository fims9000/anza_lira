# Реальный H50Z: одна команда, доказуемые файлы S86–S96 и два небольших ZIP вместо BMP >200 МБ

Этот инструмент нужен, когда реальные BMP `H50Z_030_01_405.bmp`, `406.bmp` или `407.bmp` уже есть локально, но нет возможности переслать весь 200-МБ оригинал. Он **не** пытается восстановить прежние 21 266/20 873/7 769 и другие сообщавшиеся без исходных отчётов числа. Он запускает алгоритм непосредственно по оригинальным пикселям и проверяет SHA/файлы этапов, а затем создаёт компактный диагностический пакет из **настоящих** фрагментов фотографии.

## Содержание и границы

Два разных пакета защищают от подсматривания ответа модели:

1. **`H50Z_BLIND_ORIGINAL_CROPS_PRIVATE.zip`** — только оригинальные полноразмерные PNG-кропы, те же фрагменты с нейтральным маркером целевого места, `index.html` и пустой `review_template.csv`. Никаких машинных категорий или цветных центрлиний. Это качественная проверка выбранных **машиной** объектов, а не независимое измерение recall всех физических треков.
2. **`H50Z_MACHINE_AFTER_REVIEW_PRIVATE.zip`** — открыть **после** завершения первого CSV: оригинальные пиксели слева, наблюдаемые центрлинии S86/S87 и S95-классы справа, фактически рассчитанные числа S86/S92/S95/S96, SHA-256 исходника и все выбранные категории. Физические идентичности не подтверждены.

Пакеты не включают большой оригинальный BMP, обученные веса, полный набор S86 масок или архивы другой плёнки. При двух примерах на каждую из шести категорий получается максимум 12 кропов (отсутствующие категории не заполняются вымышленными данными). Бюджет каждого ZIP — 32 МБ, иначе создание отчёта заканчивается ошибкой.

Сценарий `run` запускает **настоящие** S86 → S92 → S95 → S96 и не принимает несуществующий чекпойнт AZUNet за обученную модель. S88 — классический фильтр, а не нейросетевой ANZA фронтенд.

## Команда 1 — локально получить подтверждённый результат H50Z 405

Из корня `fims9000/anza_lira`:

```bash
git fetch origin
git switch feature/bubble-real-h50z-single-command-compact-evidence-2026-11-06

python -m pip install numpy scipy scikit-image opencv-python-headless networkx scikit-learn

python scripts/research/bubble_chamber/physicists_real_h50z_reproduce.py run \
  --bmp /PRIVATE/H50Z/H50Z_030_01_405.bmp \
  --method s88-steerable \
  --work-root /PRIVATE/results/H50Z_405_REPRODUCIBLE \
  --max-fragments-per-tile 2048 \
  --min-segment-length-px 4 --min-component-area 2 \
  --max-side 2048 --max-per-class 2 --crop-size 384
```

Точная длительность зависит от процессора, качества диска и плотности исходного кадра; заранее измеренное время не предполагается. Большой BMP читается из `np.memmap`, без одновременного помещения всей фотографии в память.

Для 406 и 407 выполните аналогично, но укажите соответствующее имя BMP и **новую отдельную** `--work-root`. Это три самостоятельных случая, а не три независимые выборки физических частиц с проверенными связями.

Если S96 требует слишком много CPU или нужна только оценка типов S95, добавьте `--skip-s96`. Если необходимо отдельно проверить раздвоенные крестовые масочные ветви, добавьте `--mask-junction-audit` (без `--skip-s96`).

**Если запуск был прерван** и соответствующий каталог S93 уже содержит `run_identity.json`, повторяйте только с `--resume` и **точно теми же** параметрами и BMP. При несовпадении SHA, модели, порогов и конфигурации повторное использование запрещено. Проверенный S95/S96 нельзя перезаписать в том же каталоге.

## Команда 2 — если настоящие S86/S92/S95/S96 уже сохранены

Вместо многочасового распознавания используйте только проверку и упаковку:

```bash
python scripts/research/bubble_chamber/physicists_real_h50z_reproduce.py pack \
  --bmp /PRIVATE/H50Z/H50Z_030_01_405.bmp \
  --s86-dir /PRIVATE/results/H50Z405_REEXECUTION/S93_SOURCES/S86 \
  --s92-dir /PRIVATE/results/H50Z405_REEXECUTION/S93_SOURCES/S92 \
  --s95-dir /PRIVATE/results/H50Z405_REEXECUTION/S95_ALL_OBJECTS \
  --s96-dir /PRIVATE/results/H50Z405_REEXECUTION_S96 \
  --private-out-dir /PRIVATE/results/H50Z405_COMPACT_AUDITED \
  --max-per-class 2 --crop-size 384
```

**Указанные пути — примеры структуры каталогов, не доказательство наличия результата на этом компьютере.** Если S96 не запускался, не указывайте `--s96-dir`. Контроль происхождения останавливает упаковку, если хотя бы один обязательный S86/S92/S95 исходный файл подменён, повреждён или принадлежит другому оригинальному BMP.

## Команда 3 — человек сначала заполняет СЛЕПОЙ CSV

Распакуйте `H50Z_BLIND_ORIGINAL_CROPS_PRIVATE.zip` в отдельную папку. Откройте `index.html`. Не открывайте `H50Z_MACHINE_AFTER_REVIEW_PRIVATE.zip` до решения.

Каждый `case_001`, `case_002` — **один машинно выбранный источник** на реальном фото, а не подтверждённый физический трек. В `review_template.csv` добавьте человеческий визуальный класс:

- `TRACK_LIKE`, `COILING_TRACK_LIKE`, `FIDUCIAL_CROSS`, `ARTIFACT`, `CROSSING_OR_BUNDLE`, `UNKNOWN`;
- `certainty`: `CLEAR` или `UNCERTAIN`;
- `note`: необязательное пояснение.

Это **классификация выбранных машиной участков**. Неразмеченные части BMP не превращаются в негативный эталон; частичная слепая разметка не даёт pixel accuracy/F1. Выбор по S95-классам — полезный практический способ посмотреть на разные типы ошибок, **но не случайная независимая выборка объектов всей фотографии**.

## Команда 4 — после ручной оценки посчитать согласование

```bash
python scripts/research/bubble_chamber/physicists_real_h50z_reproduce.py score \
  --machine-report-json /PRIVATE/results/H50Z_405_REPRODUCIBLE/COMPACT_REAL_EVIDENCE/02_machine_after_human_review/verified_machine_only_report.json \
  --completed-blind-csv /PRIVATE/results/H50Z_405_HUMAN_COMPLETED.csv \
  --private-out-json /PRIVATE/results/H50Z_405_HUMAN_VISUAL_AGREEMENT.json
```

Считает число `CONSISTENT`, `CONTRADICTS`, `UNCERTAIN` по заранее выбранным машиной линиям. Это **описательная доля согласия на предъявленных примерах**, не precision, recall, F1 и не физическое доказательство одной частицы. Контекст `CALIBRATION_CROSS_CONTEXT` S95 означает «рядом с операторским репером», а не автономную детекцию крестов; истинную морфологию по изображению определяет физик.

## Зачем это помогает в текущем чате

Если вычислительная среда ChatGPT временно не может открыть исходный BMP >200 МБ, достаточно передать сюда два **маленьких** ZIP и, позже, заполненный человеком `review_template.csv`. Пакеты сохраняют точные исходные пиксели и метаданные каждого кропа. Тогда можно обсуждать **реальные** участки, проверять визуальные ошибки машины и создавать иллюстрированный научный отчёт, не выдавая синтетические демонстрации за доказательства на H50Z.

Для статистически корректной оценки полноты реальных линий используйте отдельные S99 precommitted source-only ROI со слепой экспертной разметкой; для связности обнаруженных частей — S98. Передача только машинно выбранных примеров не может заменять эти испытания.
