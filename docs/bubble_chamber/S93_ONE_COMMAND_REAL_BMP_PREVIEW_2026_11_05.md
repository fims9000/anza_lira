# S93 — одна команда: исходный H50Z BMP → настоящее распознавание → компактный JPEG

**Ветка:** `feature/bubble-s93-one-command-real-preview-2026-11-05`, поверх PR #8 (S92), которая построена от исходной `research/bubble-chamber-graph-lira`.

Задача: получать **настоящую** аннотированную фотографию пузырьковой камеры из исходного BMP ~200–240 МБ, **не отправляя фотографии в GitHub и не загружая весь файл в память**. S86 распознаёт фрагменты изображения, S92 выполняет приоритизацию мусорных штрихов, обнаружение закрученных следов и осторожное предложение соединений разорванных фрагментов, S93 экспортирует компактный фотоотчёт и подробные кропы.

## 1. Однократный запуск по H50Z 405

На машине, где уже есть оригинал `H50Z_030_01_405.bmp`:

```bash
git fetch origin
git switch feature/bubble-s93-one-command-real-preview-2026-11-05
python -m pip install -r docs/bubble_chamber/requirements.txt

python scripts/research/bubble_chamber/physicists_s93_one_command_preview.py \
  --bmp /PRIVATE/H50Z/H50Z_030_01_405.bmp \
  --private-out-dir /PRIVATE/results/H50Z_405_S93 \
  --method s88-steerable \
  --max-side 2048 \
  --max-gap-px 26 \
  --preview-limit 12
```

При прерывании работы S86 разрешено продолжить **с теми же путями, файлом и параметрами**:

```bash
python scripts/research/bubble_chamber/physicists_s93_one_command_preview.py \
  --bmp /PRIVATE/H50Z/H50Z_030_01_405.bmp \
  --private-out-dir /PRIVATE/results/H50Z_405_S93 \
  --method s88-steerable \
  --max-side 2048 \
  --max-gap-px 26 \
  --preview-limit 12 \
  --resume
```

Файлы результата (самый нужный — второй):

- `/PRIVATE/results/H50Z_405_S93/SMALL_IMAGE/H50Z_original_small.jpg`: фотография, уменьшенная с исходной серой BMP посредством memory map, **без** новых линий;
- **`/PRIVATE/results/H50Z_405_S93/SMALL_IMAGE/H50Z_S92_annotated_small.jpg`**: тот же настоящий снимок с наложением машинного S92 выделения;
- `/PRIVATE/results/H50Z_405_S93/SMALL_IMAGE/H50Z_S92_details.jpg`: до шести оригинальных 384×384 кропов **рядом** с соответствующими S92 overlay, без изменения масштаба деталей;
- `/PRIVATE/results/H50Z_405_S93/S92/index.html`: более подробная локальная S92 галерея;
- `/PRIVATE/results/H50Z_405_S93/SMALL_IMAGE/compact_preview_manifest.json`: исходный SHA, размеры, списки и SHA выходных фото;
- `/PRIVATE/results/H50Z_405_S93/S86/` и `S92/`: проверенные неизменяемые промежуточные отчёты.

В JPEG: **голубой = наблюдаемые S92 фрагменты**, **зелёный = геометрически закрученная линия**, **пурпурный пунктир = предполагаемая кривая через пропуск**. Короткие «галочки»/«волоски» исключены только из основного слоя отображения, но остались в полном отчёте. Ни один мост не объявлен настоящим физическим соединением.

Это ***не*** результаты обученной ANZA, если выбрать `--method s88-steerable`. S88 — классический steerable/Hessian detector. Для сравнения с **реальной** AZUNet нужны подтверждённые веса в локальном приватном файле:

```bash
python scripts/research/bubble_chamber/physicists_s93_one_command_preview.py \
  --bmp /PRIVATE/H50Z/H50Z_030_01_405.bmp \
  --private-out-dir /PRIVATE/results/H50Z_405_AZUNET_S93 \
  --method azunet \
  --checkpoint /PRIVATE/models/source_locked_AZUNet.pt \
  --max-side 2048
```

Используйте отдельный каталог для каждого метода. Результаты от разных методов нельзя объединять в один отчёт. Значения S88 `0.816/1.7` унаследованы из предыдущей **синтетической** калибровки, на реальных физических снимках не верифицированы.

## 2. Как получаются маленькие файлы без исходных 207 МБ в RAM

`GrayBMP8` читает оригинальный **8-битный несжатый grayscale BMP** через `np.memmap`; S86 обрабатывает по одному тайлу 384px с halo 48px. S93 запрашивает только пиксели, попадающие в уменьшенную сетку 2048px по большей стороне. При этом не создаётся full-size RGB-копия всего исходного BMP.

Далее отрисовывается геометрия из проверенного `S92/priority_view_observed_only.ndjson`, где все пиксели имеют координаты исходного фото; гипотезы из `gap_proposals_unknown.ndjson` рисуются **отдельным пунктиром**. Из S92 preview копируются настоящие пары 384px original/overlay.

**Ограничение:** уменьшенная общая фотография может скрывать детали очень тонких треков. Поэтому в дополнение сохраняется контактный лист полноразмерных фрагментов, который необходимо просмотреть перед оценкой качества. Нельзя считать видимость линий на уменьшенной JPEG научной метрикой.

## 3. Как получить отчёт здесь, в чате

После локального запуска достаточно прислать **один готовый файл** `H50Z_S92_annotated_small.jpg` либо `H50Z_S92_details.jpg`. Никакой ручной обрезки/сжатия BMP больше не требуется. При желании можно приложить оба компактных JPEG и `compact_preview_manifest.json`.

**Почему локальный запуск остаётся необходим:** исходное вложение объёмом 206 860 918 байт здесь недоступно для программного декодирования: файлы больше 100 МБ не материализуются в доступную среду, а runtime Python/контейнера в этом диалоге возвращает ошибку. Это ограничение среды, а не невозможность обработать BMP как формат. Ветка S93 снимает необходимость вручную сжимать картинку на исходной машине.
