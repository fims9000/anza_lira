# S98 — проверяем, восстановила ли ANZA-LIRA одну видимую траекторию из прерывистых фрагментов

**Ветка:** \`feature/bubble-s98-visual-track-continuity-audit-2026-11-06\`. Родитель — S97 PR #13 → S96 PR #12 → S95 PR #11. Исходные S86/S92/S96, большие BMP и человеческая разметка остаются неизменными.

## Научная цель

Раньше S92 предлагал парные соединения, S96 выделял/сопоставлял ветви на X-пересечениях, а S97 проверял, какую долю **положительно размеченных** человеком линий вообще видит S86. Но даже при высокой доле покрытых пикселей одна длинная человеческая траектория может состоять из множества непересекающихся наблюдаемых фрагментов.

S98 устраняет конкретный пробел в проверке: **не спрашивает, насколько красиво алгоритм соединил только те пары, которые сам выбрал**, а сначала по независимой человеческой кривой выявляет, где детектор создал две отдельные наблюдаемые части **одной видимой 2D линии**. Только **после формирования списка таких границ** проверяет, предлагали ли S92/S96 соответствующее продолжение.

**Это не полная физическая связность частиц.** Две части могут казаться одной линией в проекции, но принадлежать разным частицам. Спираль не означает доказанное нейтронное столкновение. Для физической идентификации нужны другие данные и экспертиза.

## Что именно измеряет S98

Для каждого **CLEAR / TRACK_LIKE или CLEAR / COILING_TRACK_LIKE** контура из S97:

1. Разбиваем операторскую 2D полилинию на точки с шагом ~1 исходный пиксель.
2. На каждой точке ищем **ближайший исходный наблюдённый фрагмент S86/S87**, в пределах фиксированного радиуса (по умолчанию 2 пикселя). Псевдомосты из S92/S96 не считаются обнаруженными пикселями.
3. При конкуренции двух разных фрагментов почти на одинаковом расстоянии отказываемся от присвоения одного из них: \`ambiguous\`.
4. Требуем минимальную устойчивую длину наблюдаемого участка (3 исходных пикселя по умолчанию).
5. По порядку следования человеческой кривой находим пары **соседних устойчивых исходных наблюдаемых фрагментов**, разделённых не более 80 px вдоль человеческой кривой. Если разрыв слишком большой, ответ остаётся неизвестным.
6. Когда один исходный фрагмент одновременно поддерживает несколько независимо названных человеческих линий, он помечается как **слитый/неразрешённый**: такие границы исключаются из оценимого знаменателя.
7. После фиксации полученных границ проверяем, выбрали ли S92 или S96 точно соответствующую пару ID исходных фрагментов.

Именно это позволяет увидеть разницу между случаями **«нашёл линию, но разбил на 7 кусков»** и **«нашёл и правильно связал наблюдаемые куски»**.

### Важные названия метрик

- \`observed_source_centerline_positive_coverage\`: старый S97 — доля уверенно размеченных положительных точек, у которых рядом реально наблюдена линия S86;
- \`unique_source_components_near_this_human_trace\`: число различных исходных S86/S87 объектов вдоль одной размеченной кривой. Чем больше число, тем больше сегментация дробит визуальную линию **при сопоставимом покрытии**;
- \`assessable_unique_detected_piece_adjacencies\`: число независимых соседств **уже обнаруженных** фрагментов одной человеческой линии, которые можно проверить без конфликта визуальных ID;
- \`conditional_reference_piece_boundary_selected_coverage\`: доля этих соседств, для которых S92/S96 выбрали соответствующую пару;
- \`union_selected_conditional_coverage\`: доля этих соседств, покрытых **хотя бы одним** из фактически переданных в команду S92/S96 вариантов;
- \`reference_boundaries_missed_by_all_selected_models\`: отдельные пропущенные предложения, которые можно увидеть на исходном фото **после** независимой разметки.

Если S86 пропустил все пиксели трека, то **положительное покрытие 0**, но количество наблюдаемых соседств тоже 0, а их доля покрытия — \`null\`, а не «идеальное восстановление». Если не передали S92/S96 вообще, оценка их выбора **NOT_EVALUATED**, а не 0.

**Это условное покрытие межфрагментных границ, а не recall всех настоящих физических трековых связей.** Для полной полноты нужны независимо предъявленные экспертные пары/идентификаторы всего события, включая фрагменты, не обнаруженные моделью.

## 1. Подготовка: сначала завершить S97, БЕЗ машинных предсказаний при разметке

Подробнее: [S97 independent reference](S97_INDEPENDENT_EXPERT_REFERENCE_BENCHMARK_RU_2026_11_06.md). Исходный \`/PRIVATE/H50Z/H50Z_030_01_405.bmp\` разметить в приватной странице S97 \`index.html\` и экспортировать \`S97_independent_human_trace_reference_PRIVATE.json\`.

Без таких независимых оригинальных исходных данных S98 может проходить только **синтетические инженерные тесты**, результаты нельзя выдавать за качество ANZA-LIRA на H50Z.

## 2. Запуск по двум версиям S86 и соответствующим им гипотезам S92/S96

Все пути ниже — примеры интерфейса, не заявления о наличии артефактов в этом репозитории.

\`\`\`bash
git fetch origin
git switch feature/bubble-s98-visual-track-continuity-audit-2026-11-06

python scripts/research/bubble_chamber/physicists_s98_trace_continuity.py \

  --candidate S88=/PRIVATE/results/H50Z_405_S88_S86 \
  --candidate AZUNET=/PRIVATE/results/H50Z_405_AZUNET_S86 \
  --s92 S88=/PRIVATE/results/H50Z_405_S88_S92 \
  --s96 S88=/PRIVATE/results/H50Z_405_S88_S96 \
  --radius-px 2 \
  --max-reference-gap-px 80 \
  --max-visual-cases 16 \
  --private-out-dir /PRIVATE/results/H50Z_405_S98_CONTINUITY
\`\`\`

Можно передать \`--s92 AZUNET=...\`, \`--s96 AZUNET=...\` **только если они были действительно запущены на точно соответствующем AZUNET S86 пакете**. При несовпадении SHA S86 или BMP анализ прерывается. Если нет конкретных версий S92/S96, достаточно \`--candidate\` — измерение числа фрагментов всё равно доступно, а модельные связи остаются *не оценены*.

## 3. Результаты

- \`report.json\`: все показатели по каждому детектору на **одних и тех же** человеческих позитивных полилиниях, исходные SHA S86 и исходного BMP, перечень независимых наблюдаемых границ, число неоднозначных пересечений и результаты S92/S96 по каждой границе.
- \`index.html\`: сравнение вариантов по покрытию, числу разрозненных фрагментов и доле предложенных соседств.
- \`cases/\`: по умолчанию до 16 **пропущенных алгоритмами предложений** с оригинальными 2D фото-кропами. Слева неизменённый исходный снимок; справа он же с **двумя наблюдаемыми фрагментами**, экспертной независимой линией и центром разрыва. Система ничего не дорисовывает в исходные данные и не маркирует как установленное физическое соединение.

### Что нельзя выводить из этих результатов

1. **Меньше исходных фрагментов ≠ лучше модель.** Модель с нулём обнаруженных треков имеет нулевую фрагментацию, но полностью провалила обнаружение. Сравнивать обязательно вместе с S97 покрытием и пропусками.
2. **Согласие с операторским визуальным ID ≠ одна физическая частица.** При 2D пересечении нельзя исключить наложение следов разных частиц.
3. **Совпадение с S92/S96 ≠ улучшение recall всего алгоритма.** Это оценка только тех последовательных наблюдаемых S86-фрагментов, которые представлены в явной человеческой разметке. Полностью не обнаруженные линии туда не входят.
4. **Плотные и слипшиеся X-пересечения** нужно отдельно разбивать и оценивать в режиме S96 \`--mask-junction-audit\`. S98 помечает смешанное визуальное происхождение исходных фрагментов как неоднозначность.
5. **Результат на одном H50Z нельзя считать независимым тестом.** Для публикации — несколько независимых кадров и событий, фиксированный split по плёнкам, экспертная разметка до вывода машинных результатов, сравнение по группам физических событий.

## 4. Следующий научный эксперимент

- Выбрать независимые оригинальные ROI, включающие **обычные длинные треки, короткие истинные штрихи, реперные кресты, участки X/Y, пучки и спирали**.
- Дать 2 физикам самостоятельно разметить их в S97; найти согласованные CLEAR положительные линии, спорные случаи исключить либо явно разобрать третьим специалистом.
- Для каждого зафиксированного набора запустить **одинаковые** детекторы S88/AZUNet и одинаковые настройки межфрагментных соединений. Нельзя на одной серии подбирать пороги и потом предъявлять её как независимый тест.
- Сравнить S97 обнаружение реальных 2D линий и S98 условную целостность наблюдённых частей. Документировать не только средние, но частные ошибки и изображения с правильным SHA.

**На момент создания S98 — только синтетические тесты кода. Не было новых замеров точности на реальном H50Z, и это ограничение остаётся принципиальным.**
