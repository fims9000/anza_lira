# S85 Interop v2: detector-specific TRAIN/CAL/TEST on entirely GENERATED images

**Protocol frozen before the first v2 benchmark run; 2026-10-28.**

This is a **developer QA**, NOT scientific proof about native H50Z or real particle associations. No private H50Z or visualMetro source data is accessed. This deliberately tests whether detector-specific calibration changes the conclusions of the previous uncalibrated toy comparison; it does **not** transfer calibration policies to real photographs.

- Independent RNG seeds: TRAIN `20268610`, CAL `20268611`, TEST `20268612`. TRAIN 24 scenes, CAL 16 scenes, TEST 24 scenes. New generated grayscale 512x512 textured backgrounds in each split, independent artificial curved templates per split (no reuse of simulated source template IDs across partitions). Every generated scene has 2 true synthetic three-piece chains and 1 injected decoy; scenario schedule identical across detectors. Three pixel conditions paired by scene: clean, Gaussian blur `sigma=1.1`, scratch/grain. Avoid splitting transformed versions of the same scene into different splits.
- Three pixel-only detector families: existing Hessian ridge extraction, OpenCV LSD and Hough-P, all max 12 polylines. Freeze their built-in parameters. Artificial oracle is evaluator-only control and is not trained or deployed.
- `S59` strictly gates pairs; use `GEOMETRY_FIELDS` only (no ANZA activations, no image source reference) and `StandardScaler + LogisticRegression(C=1, class_weight='balanced', solver='liblinear', random_state=20268613, max_iter=200)`. Fit **separate** detector weights from TRAIN pairs only. Positive labels require association to one of the four injected valid adjacent pairs AND synthetic correct facing endpoints; all others are synthetic noncorrect proxy negatives. Never call them confirmed false *native* tracks. If TRAIN has fewer than 6 positive pairs, 12 negative pairs or 4 distinct positive-source scenes, that detector returns an abstaining model (all predicted probabilities=0) and is not “trained”.
- CAL per detector per strategy `node_mutual`, `port_greedy`, `global_milp`: thresholds `[0.50,0.65,0.80,0.90,0.97]`, frozen `margin=.04` and per-solver-call MILP budget `0.12 seconds` (not an end-to-end deadline). For each arm, choose a threshold on CAL maximizing lexicographically full artificial paths, correct links and fewer extras, **subject to** CAL all-conditions noncorrect proposals `<= floor(correct/4)` AND every individual condition noncorrect `<= floor(correct/4)` AND total correct>=2. If none qualifies, choose `threshold=1.0` (abstain). `none` is the safety control. Then independently choose the best strategy from CAL-passing arms with same objective, including `none`. All strategies and CAL selections are frozen before TEST.
- TEST on untouched 24 scenes x3 conditions, report frozen model SHA-256, CAL thresholds, correct/noncorrect synthetic joins, complete 3-piece chains, candidate coverage, solver failures, per-scene paired 1200-bootstrap CI for `global_milp - port_greedy`. Evaluate **only after** blind pixel predictions; no identity/source nodes enter any detector, feature scorer or solver. No TEST retuning. No physical joining authorization.
- Key hypotheses and falsifiers: (i) detector-specific training+CAL could reduce spurious joins vs one global uncalibrated geometry heuristic; (ii) extra global complexity need not improve chain completion under strict risk; (iii) curved vs straight detector choice dominates if there are insufficient fragments. A zero-join abstention is an honest *negative* result, not a success.

No native H50Z physical GT or independent runs are added by this synthetic toy. Do not change S72 or release any automatic real-physics linking from this study.
