# Developer integration addendum: detector-calibrated experiment and safe crop mapping


Теперь реализованы две дополнительные части для разработчиков:

1. `interop_coordinates.py`: строго заданная *неизменяемая* 192×192 область исходного изображения, преобразование `(x,y)` из координат кропа в исходные пиксели 512×512 и обратно без молчаливого изменения масштаба. Опциональный `private_review_payload` экспортирует исходные координаты **только для закрытого интерфейса**, а `result.as_public_dict()` их не содержит.
2. `interop_verified_runtime.py`: `process_verified()` требует detector-specific `CalibrationReceipt`, хеши приватной модели и SOURCE-CAL, точный `training_domain_id` и уровень доказательности. Сигнатура не содержит ground truth. При несовпадении данных **ошибка, а не скрытый fallback к чужой модели**. Само поле `validation_level` задаётся разработчиком и не является внешним подтверждением физической точности.

**Новый контрольный тест**, `S85_INTEROP_CALIBRATED_RESULT_2026_10_28.md`: на отдельно сгенерированных TRAIN=24/CAL=16/TEST=24 сценах обучены собственные геометрические классификаторы для Hessian, LSD и Hough. На CAL все три не выполнили заранее замороженное ограничение доли синтетически неправильных соединений (максимум 1 на 4 правильных), поэтому **на TEST все отказались от соединений**. Это честный отрицательный результат для текущего сочетания признаков, риска и искусственных данных. Он не доказывает безусловное превосходство Hessian, нейронной сети или MILP в иных доменах и не заменяет новых реальных физических GT.

**Важный API предел:** текущий S56 `pair_rows` принимает 3–32 линии; при 0–2 входных линиях `process_image` возвращает ровно ноль соединений. Это осознанная привязка к трёхфрагментной модели и ограничение при интеграции в другой продукт, а не подтверждение отсутствия реального соединения между двумя фрагментами. Если нужны пары из 2 фрагментов, проектируйте отдельно и валидируйте двухфрагментный режим; не меняйте молча замороженный S56.

**Тайм-аут:** `global_milp` многократно вызывает MILP при проверках неоднозначности, поэтому параметр `solver_timeout` ограничивает отдельный вызов, **не общую задержку** обработки одного снимка. Для веб-сервисов необходим внешний deadline, request cancellation и fallback to `none`. Сами рекомендательные связи `UNKNOWN` и должны быть обратимыми.
