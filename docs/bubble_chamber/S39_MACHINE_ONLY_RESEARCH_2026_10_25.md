# S39 — автономная машинная псевдоразметка H50Z и контроль физической интерпретации

**Дата:** 25 октября 2026 года. **Рабочая ветка:** `research/bubble-chamber-graph-lira`.

**Главное решение:** этап S38, требовавший ручной работы пользователя, не блокирует исследования. В S39 создан полностью автоматический конвейер обнаружения фрагментов, генерации разреженных машинных псевдомасок, построения обратимого графа гипотез соединений и независимой технической проверки. Пакет для физиков формируется без ручной разметки. **Никакие не подтверждённые физиками гипотезы не выдаются за ground truth**.

## 1. Источники и их смысл

- Оригиналы: `H50Z_030_01_005.bmp` (9020 × 26151 px) и `H50Z_030_01_006.bmp` (9268 × 25324 px) из одного архива/физического запуска. Извлечены локально системной `libarchive`, проверены исходный 7z SHA-256 и формат BMP (8-битный grayscale). В публичный Git не добавлены.
- 39 ранее подготовленных 512×512 H50Z-кропов — **целевая, заведомо смещённая выборка** для детального сравнения моделей; в ней 133 старых машинных линии, 28 вопросов о соединениях и 17 участков без машинных предложений.
- Архив `1mH2Data` / visualMetro: 145 целых пригодных кадров плёнки 070, 1073 измеренных оператором трека и 17321 пространственный отсчёт; эти координаты соответствуют **другому материалу, не фотографиям H50Z**. Их можно использовать как шаблоны геометрии для контролируемых имитаций, но не в роли настоящих масок H50Z.
- Исходная AZUNet использует штатные исходники и S33 machine-mask-trained контрольные веса. Для фотографии 005 используется модель с обучением на 006, и наоборот. Это **фотографически раздельная, но НЕ независимо-run-disjoint** проверка.

**Два научных источника, которые уже были предоставлены:** Беляев А. В., Бушмина Е. А., Клевцова Е. А., *Руководство пользователя по работе с программой visualMetro для измерений треков на фотографиях с пузырьковых камер* (Дубна, 2025); Беляев А. В., *Нахождение массы заряженной частицы по форме её траектории…*, ОИЯИ P1-2023-22 (2023). Первый требует проекций и калибровок для 3D, второй ограничивает адроиду особым случаем остановки в магнитном поле. Поэтому ни одна универсальная 2D-линия S39 не рассматривается как подтверждённая «адроида» или основа для вычисления массы.

## 2. Алгоритм S39

1. Проверка SHA-256 исходного ZIP, реальных декодированных пикселей и provenance машинных черновиков; контроль того, что веса AZUNet относятся к другой фотографии.
2. Локальное выравнивание яркости без глобального порога, вычисление положительной нормальной кривизны и штрафа за blob-like изотропную структуру в трёх масштабах σ=1.1/2.2/3.5 px.
3. Ограничение доли активированных пикселей; скелетизация, обрезка областей ветвлений, выделение геодезических сегментов, отсев совсем коротких и вырожденных геометрий.
4. Сопоставление с линиями S31, измерение реального локального контраста «центр – боковые полосы», мульти-масштабной устойчивости, согласования с AZUNet и близости к старым гипотезам.
5. Формирование **разреженных машинных псевдомасок**: `1` = предварительный машинный центр линии; `0` = *лишь предположительно* соседний фон вдали от известных предложений; `255` = неизвестно. В особенности 255 не является отрицательным классом, а 0 нельзя считать экспертной отрицательной разметкой.
6. Граф фрагментов: удаление практически дублирующихся центральных линий, измерение расстояния между концами и согласованности наружных касательных, построение сплайновой гипотезы мостика; конкурирующие продолжения исключаются из набора однозначных предложений. **Никаких физических соединений автоматически не выполняется.** Граф-кандидат в S39 является геометрическим модулем и **не подменяет обученную CT28 relation head**.
7. Отдельная пространственно сбалансированная слепая выборка 64 плитки с каждой полной BMP, чтобы не делать вывод по только заранее выбранным 39 кропам.

## 3. Реальные H50Z: что получила машина

| Измерение | Фактически получено |
|---|---:|
| Ранее имевшиеся машинные черновики линий | 133 |
| Дополнительные машинные линии (многомасштабный алгоритм) | 434 |
| Всего предложений до подавления дубликатов | 567 |
| Прежде пустых участков, теперь с гипотезами | 17 из 17 |
| Машинные условно положительные центральные линии | 516 |
| Машинные условно положительные пиксели, **не GT** | 101051 |

**Слепая проверка пространственного охвата:** `128` заранее выбранных неперекрывающихся участков двух исходных BMP, равномерно распределённых по восьми вертикальным зонам. Кандидаты найдены на 127 участках из 128; собрано 1166 машинных линейных сегментов. Для 24 участков дополнительно рассчитан выход AZUNet, обученной на противоположной фотографии. **127/128 — это частота генерации гипотез, а не оценка точности/полноты частиц.** В частности, очень высокая частота предложений может означать и нежелательную реакцию на царапины сканера.

**Граф связей:** 511 геометрических узлов после устранения практически дублирующихся линий, 182 предположительных соединений, 70 уникальных по конкуренции предложений; 112 альтернатив отложено как неоднозначные. Критерий «однозначно» относится лишь к геометрическому рейтингу внутри одного изображения и не является физическим доказательством принадлежности фрагментов одной частице.

## 4. Контролируемая проверка обнаружения, без подмены натуральной истины

Протокол: 40 новых искусственно зашумлённых сцен на каждом тестовом фоне 005 и 006 (всего 80), по 4 заранее определённым сценариям. Контур заимствован из другого фильма visualMetro; он затем добавляется на H50Z **искусственным тёмным штрихом** с известной маской и отдельным мешающим штрихом. Из 145 полных кадров visualMetro 109 не входят в проверку и 36 оставлены для тестовых форм. Никакой нативный пиксель H50Z не получает GT-маску.

Каждый метод выделяет ту же фиксированную долю 3,5% пикселей, где имеется достаточная пространственная вариативность его оценки. Метрика ниже — доля пикселей **искусственно внедрённой линии**, возле которых на расстоянии не больше 2 px сработал детектор; её нельзя называть Dice, полнотой или точностью на настоящих частицах.

| Алгоритм | 005, искусственные линии | 006, искусственные линии | 005, искусственная царапина | 006, искусственная царапина |
|---|---:|---:|---:|---:|
| Локальная темнота / контраст | 79.81% | 81.88% | 88.27% | 85.51% |
| Трёхмасштабный детектор хребтов | 77.87% | 79.75% | 80.54% | 79.96% |
| Градиент Собеля | 67.39% | 65.25% | 71.35% | 67.11% |
| Оригинальная AZUNet, обучение на другой фотографии | 38.71% | 56.26% | 34.12% | 53.17% |
| Хребты + AZUNet (ранговая комбинация) | 55.04% | 70.07% | 49.17% | 67.64% |
| Хребты + локальный контраст (ранговая комбинация) | 79.03% | 80.51% | 84.56% | 82.16% |

**Интерпретация:** ANZA показывает меньшую полноту обнаружения внедрённых линий, но также в среднем реже активируется на отдельно введённой царапине. Локальный контраст лучше по полноте, однако и сильнее реагирует на ложный штрих. Нельзя объявить общего победителя на основании одной этой метрики; задача различения реальных частиц/сканерных дефектов остаётся открытой. Многомасштабная геометрия сейчас полезнее как *генератор кандидатов*, а не как готовый классификатор физических треков. Интервалы в JSON построены бутстрэпом синтетических сцен: они **не характеризуют перенос на независимые физические запуски**.

## 5. Демо для физиков и машинные файлы

Сформирован ZIP `ANZA_LIRA_S39_PRIVATE_MACHINE_DEMO.zip`. Распаковать, открыть `ANZA_LIRA_S39_MACHINE_ONLY_DEMO/index.html`; HTML автономен и не обращается в интернет.

- Для каждого из 39 фрагментов: оригинальная картинка, наложенные машинные линии, **пунктирные** предлагаемые мостики и трёхсостояние псевдомаски.
- Независимо выбранные (не по наилучшим оценкам) участки полных BMP показывают общую работу сегментатора на разных фонах.

- Подробные `S39_MACHINE_HYPOTHESES_PRIVATE.json`, `S39_GRAPH_RELATIONS_PRIVATE.json`, `S39_FULL_BMP_CANDIDATES_PRIVATE.json` остаются в закрытом рабочем каталоге и не коммитятся.

**В приватном браузерном QA:** все PNG загрузились, переключение двух фото и шести родов областей проверено, ошибок выполнения JS нет, ZIP выдержал CRC проверку.

## 6. Научные ограничения и что делать автоматически дальше

- **Никаких действий пользователя по ручной разметке не требуется** для продолжения исследования, формирования машинных данных и демонстрации. Когда физики смогут оценить результат, их заключения будут отдельной последующей валидацией, а не предварительным условием текущего этапа.
- Сейчас отсутствуют физические достоверные маски реальных H50Z-треков, пары same/different, полные сопряжённые три BMP одного события и run-specific физические калибровки. Поэтому **нельзя измерить** реальную false-join rate, физический PID, 3D-направление, массу, истинную полноту обнаружения на H50Z.
- Метки машинного согласия/теневого фона должны иметь вес **ниже**, чем экспертизная GT, и не должны использоватся для подгонки оценочного теста. Самосогласие двух моделей, обученных на похожих псевдомасках, не является доказательством правильности.
- Логичный полностью машинный следующий опыт: контролировать ложные полосы на известных реперах и детекторах царапин; запускать фотометрические perturbation-consistency и negative controls; обучать только на надёжном ядре псевдомасок, а не на 516 гипотезах без фильтра; сохранять исходный graph abstain. Отдельно оценивать способность отличать тёмные штрихи от настоящих траекторий на синтетически введённых мешающих объектах.
