# S100 — геометрические кресты без операторских f1…f8

## Постановка

S95 ранее использовал категорию `CALIBRATION_CROSS_CONTEXT` **только рядом с уже известной меткой реперного креста**, а не за счёт самостоятельного распознавания креста. Задача S100 — найти **X-образные структуры в пиксельных следах без координат f1…f8**, не объявляя их реперами, одной физической частицей или событием взаимодействия.

Проблема: в одной 2D фотографии пузырьковой камеры четыре луча могут образоваться из:
- отдельной калибровочной метки/креста;
- двух не связанных физических треков, случайно наложившихся при проекции;
- настоящей вершины взаимодействия;
- царапин и артефактов, пересекающихся со следом.

**Геометрия четырёх лучей не идентифицирует физическую причину.** Даже аккуратное распознавание X не является достоверным распознаванием репера без дополнительного пространственного/физического контекста. Машинные категории S95 остаются нетронутыми, S100 создаёт отдельный слой гипотез.

## Откуда берутся кандидаты

S100 работает с двумя **строго различными представлениями**:

1. `ORIGINAL_S86_COMPONENT_ENDPOINTS` — уже разделённые оригинальные наблюдаемые компоненты S86/S87. S96 ищет места, где рядом заканчиваются 3, 4 или 5+ фрагментов.
2. `VERIFIED_S86_MASK_SPLIT_ARMS` — дополнительные, независимо сформированные ветви на оригинальной бинарной маске S86, если S96 запущен с `--mask-junction-audit`. Это позволяет увидеть некоторые кресты, которые обычная полилиния S86 ошибочно сохранила одним слитым компонентом. Ветки не заменяют исходный S86 и не считаются самостоятельными физическими треками.

Файлы проверяются по SHA исходного BMP и всей цепочке S86→S92→S95→S96. Для ветвей маски S100 **дополнительно проверяет фактические координаты каждого пикселя**: центр линии должен лежать на бинарном foreground соответствующей оригинальной маски, её SHA и ID должны совпадать с S86. Концы и направления каждого исходного S96 луча проверяются независимо относительно неизменённой S86 полилинии. Подмена mask-derived пикселя отвергается до создания отчёта.

## Как определяется геометрическое X

1. Нужно **ровно четыре различных наблюдаемых луча**, каждый со своей исходной идентичностью. Три луча (Y) или пять и более (пучок) — **отказ**, а не искусственное превращение в X.
2. Концы лучей должны действительно находиться в окрестности одного центра: по умолчанию не далее 14 пикселей и с диаметром группы не более 22 пикселей.
3. Перебираются **три возможных разбиения четырёх лучей на две непересекающиеся пары**.
4. У каждого из двух потенциальных направлений противоположные касательные должны сходиться почти на одну прямую (максимальный излом по умолчанию 30°).
5. Две найденные оси должны пересекаться под достаточно выраженным углом (острый угол **не менее 35°**). Почти параллельные полосы отклоняются.
6. Лучшее разбиение должно явно превосходить следующее по суммарному угловому критерию (по умолчанию минимум 10° преимущества). Нет убедительного варианта — `AMBIGUOUS_PAIRING_ABSTAIN`.

Успешный результат получает категорию `FOUR_ARM_GEOMETRIC_X_REVIEW_NOT_FIDUCIAL_IDENTITY`, **без вероятности, не откалиброванной на реальных данных**, и две условные пары лучей. Пары остаются **гипотезами визуального продолжения**, между концами лучей не добавляются «обнаруженные» пиксели.

Для mask-derived и original совпавшие рядом центры помечаются близкими альтернативными представлениями **без смешения ID и без двойного счёта физических событий**.

## Один запуск с исходного BMP — все этапы S86→S100

Если прежние промежуточные файлы не сохранились, можно запустить весь конвейер одной командой. S100 — новый самостоятельный диагностический этап, он не меняет маски и классификацию S95:

```bash
git fetch origin
git switch feature/bubble-s100-unlabeled-cross-shape-review-2026-11-06

python scripts/research/bubble_chamber/physicists_real_h50z_reproduce.py run \
  --bmp /PRIVATE/H50Z/H50Z_030_01_405.bmp \
  --method s88-steerable \
  --work-root /PRIVATE/results/H50Z405_S100_FULL \
  --mask-junction-audit --s100-cross-review \
  --s100-review-limit 12 \
  --max-per-class 2 --crop-size 320
```

Для исходного `406.bmp`/`407.bmp` подставьте новые пути BMP и новые рабочие каталоги. Если прервался запуск, добавьте `--resume` **с теми же** параметрами: законченные S86/S92/S95/S96 и исходные BMP проверяются; готовый ZIP S100 повторно открывается с побайтной проверкой оригинала на каждой фотографии. При изменении исходного изображения, SHA, конфигурации или PNG упаковка отвергается, а не молча перезаписывается.

При наличии настоящего обученного checkpoint можно выполнить отдельный `--method azunet --checkpoint ...` и сравнить результаты. **Нельзя** просто переименовать результаты классического фильтра S88 в AZUNet.

После успешного запуска изображения и архив с исходными фото-кропами лежат в `/PRIVATE/results/H50Z405_S100_FULL/S100_UNLABELED_X_CROSS_SHAPES/`. Их можно передать для разбора ошибок **без загрузки 200-МБ BMP**.

## Запуск на настоящем H50Z 405 из уже сохранённых каталогов

Нужны сохранённые приватные каталоги S86/S92/S95/S96 от **одного и того же** BMP. Если их нет, воспользуйтесь сначала `physicists_real_h50z_reproduce.py run` с `--mask-junction-audit` из PR #17.

```bash
git fetch origin
git switch feature/bubble-s100-unlabeled-cross-shape-review-2026-11-06

python scripts/research/bubble_chamber/physicists_s100_unlabeled_cross_review.py \
  --bmp /PRIVATE/H50Z/H50Z_030_01_405.bmp \
  --s86-dir /PRIVATE/results/H50Z405/S93_SOURCES/S86 \
  --s92-dir /PRIVATE/results/H50Z405/S93_SOURCES/S92 \
  --s95-dir /PRIVATE/results/H50Z405/S95_ALL_OBJECTS \
  --s96-dir /PRIVATE/results/H50Z405/S96_JUNCTIONS \
  --case H50Z405 \
  --max-preview-cases 12 --crop-size 320 \
  --private-out-dir /PRIVATE/results/H50Z405_S100_X_REVIEW
```

Здесь имена каталогов — **образец расположения файлов**, их реальное существование не предполагается. Для 406 и 407 используются отдельные входные и выходные каталоги.

### Результаты

- `candidates.ndjson` — вся геометрия каждого рассмотренного X/Y/пучка, исходные S96 ID, тип источника, причина принятия или отказа, две условные пары и флаги отсутствия физической идентификации.
- `report.json` — число проверенных S96 оригинальных и S96 масочных кандидатов, причины отказов, SHA входных источников, точное происхождение бинарных пикселей.
- `index.html` — на **реальном оригинальном BMP** слева исходные неизменённые пиксели, справа те же пиксели с линиями на основе реально наблюдаемого S86/маски, точками на концах и центром геометрической гипотезы. Промежуточный «мостик» не дорисовывается как реальный трек.
- `S100_REAL_SOURCE_X_SHAPE_DIAGNOSIS_PRIVATE.zip` — небольшой приватный архив предыдущих файлов и PNG, размер не более 32 МБ. Полного исходного BMP и весов нет.

Галерея S100 выбирается **на основании машинных кандидатов**. По ней можно найти и показать неудачные кресты, ложные пучки или геометрические отказные случаи, но нельзя оценивать precision и recall на всей фотографии: пропущенные системой кресты в галерею не попадают.

Для настоящей оценки независимый специалист должен размечать **исходные S99, предварительно выбранные независимо от модели ROI** с категорией `FIDUCIAL_CROSS` до просмотра S100, а затем сопоставлять по источнику и пространственному положению. Для спорных физических случаев необходимо экспертное подтверждение.

## Исследовательский вывод, который пока делать нельзя

Пока нет независимой экспертной разметки и проверки на реальных H50Z, нельзя утверждать, что:
- найденные X действительно являются реперными крестами;
- найденные пары — части одной частицы;
- отсутствие пары означает «мусор»;
- добавление S100 улучшило качество ANZA-LIRA.

CI S100 проверяет реализацию на синтетическом **отчётливо маркированном** исходном BMP, включая слитый X, а также Y, пучок, почти параллельные структуры, подмену исходных масок, оригинальные пиксели и SHA.
