# V37 — минимальная независимая диагностика несовпадения весов ANZA/U-Net на разных CPU runners

**Предварительно зафиксировано 14.11.2026 до результатов V37.** V36: два новых runners совпали между собой побитово, но не совпали с оригинальным V35, хотя SHA обучающих патчей, нормализация и сохранённые настройки были одинаковы. Причина не установлена. Не менять прежние V33–V36 численные результаты и не открывать Thebe TEST7.

## Протокол

На **двух независимых** GitHub runners с Python 3.11, PyTorch 2.5.1+cpu, единственным CPU thread, MKLDNN disabled и deterministic_algorithms=True создать исходные архитектуры AZConv-v1 и U-Net при исходных seed 20263311/20263312. Никаких скачиваний данных Thebe и никаких реальных моделей P0.

На одних и тех же детерминированных числовых тензорах 64x64 снять SHA256 (с именами и dtype) по состояниям:

- начальное состояние параметров сразу после seed + `build_comparable_model`;
- выход прямого прохода на фиксированном input;
- градиенты `binary_cross_entropy_with_logits` до оптимизатора;
- параметры после **одного** шага AdamW;
- текстовая CPU/processor/system/PyTorch информация и hash входов.

При отсутствии совпадения начальных весов расследовать seed/среду. Если начальные веса совпадают, но логиты/градиенты отличаются, расследовать CPU operation dispatch. Если совпадает один шаг, но реальные TRAIN 600 шагов отличаются, запросить промежуточные состояния на реальных TRAIN и первую расходящуюся итерацию без TEST7.

**Никаких заявлений о реальном качестве сегментации** по этому тесту. Он проверяет только возможность побитовой репликации математики на фиксированных небольших данных.

Не использовать VAL2 и TEST7, не переобучать опубликованные V33/V34 и не изменять пороги задним числом.
