## Correcting an important architecture claim

V27/V28 used a 12-numeric-feature **sklearn LogisticRegression** relation scorer, called "new LIRA" as a functional pair selector. It **did NOT execute the original P0 LIRA five-convolution context model**. V30 reuses actual repository \`path_completion.pair_classifier.EndpointPairClassifier\` (five convolutions, GroupNorm, GELU, mean/max feature readout and linear head) as a newly fitted P0-*architecture* experimental LIRA. Original \`oriented_pair_crop\` produces an observed 33×49 context tensor with SIX channels: 3 observed original RGB image channels, one segmentation-predicted binary visible mask, two Gaussian-coordinate/corridor fields based ONLY on **SBPP-predicted** source/candidate pair locations. Never use expert trace pixel, expert true endpoint or hidden context to construct an input. TRAIN expert labels may annotate candidate supervision and CAL risk; TEST expert truth may only score after all fitted models and risk thresholds are frozen.

## Frozen P0 training and comparators

- For each frontend, collect **only TRAIN SBPP-predicted candidate pairs** (strictly source-section-grouped). Require at least eight true and eight false pairs; otherwise explicit STOP and no CNN claimed. V28 reported 35 positive ANZA and 27 positive U-Net TRAIN pairs, but this design is subsequent to seeing those training counts.
- Build a TRAIN-only *matched* context dataset: for each positive candidate, select at most one geometrically hard negative **from the same controlled TRAIN scene**; otherwise from another TRAIN scene with nearest candidate distance. Unique negative pairs, no heldout scenes and no downsampling of positives. Data pairs never cross TRAIN/CAL splits. Each image-context array gets four deterministic vertical/horizontal flips (no oracle features) to train, labels 1/0. Record matched 1:1 counts and originating TRAIN section IDs.
- Train true P0 \`EndpointPairClassifier\` from scratch on observed original seismic context for **30 epochs** fixed, batch32, AdamW lr=.001 weight_decay=.0001, BCEWithLogitsLoss, no CAL-driven early stopping. **Two true independent seeds 11 and 23**; single-thread deterministic CPU. Save original \`EndpointPairClassifier.state_dict\` SHA256 for both; report train BCE early/late and no output interpreted as calibrated probability. This is an architecture-fidelity test, not recovery of original 120-epoch synthetic P0 training budget.
- Controls: (i) same matched TRAIN candidate pair examples with fixed 12-feature supervised LogisticRegression + scaler, (ii) existing *full* TRAIN logistic scorer over every TRAIN predicted pair (V28 policy), (iii) geometry score. Do not equate matched logistic with full-data logistic; report both and the unequal labels admitted by the full scorer.
- CAL-only choose an acceptance threshold from \`{0,.05,...,1.0,1.01}\` per frontend+method with 0 accepted wrong link among four CAL positive worlds and 0 accepted fake NO_LINK among four CAL negative worlds (this is the strict discrete consequence of the old 10% empirical caps on n=4). Optimize number of *correct accepted* CAL positive worlds, ties prefer fewer false/wrong and then larger threshold. Freeze all model weights, input normalization, thresholds, source sections before loading TEST pixels. If a method cannot show accepted correct CAL links safely, freeze **never-link**; do NOT reselect threshold after TEST. Log ranking-only (ungated) top1 correctness as separate diagnostic without promoting it.
- MAIN TEST on same previously inspected 108/124 sections: stage-by-stage attrition; four method+frontend combination outcomes (actually five per frontend because P0 two seeds); candidate availability, correct candidate presence, top1 correctness, accepted positive links, false accepted synthetic NO_LINK, path success from observed evidence, and exact case-level scores. Strong transparency: TEST has ONLY two source sections and artificial intervention boxes; failures MUST remain failures, no pseudoreplication by candidate windows.

## Acceptance and claim limit

V30 can establish whether a **newly trained original P0 CNN ARCHITECTURE** can consume real **ANZA-predicted SBPP ports** and rank pairs. It cannot establish the historical original P0 weights, true geological instance identity, naturally occurring disconnections, generalization to independent seismic volumes, or superiority over published seismic segmentation models. It must distinguish "P0 fitted and ranked" from "P0 safely admitted" and "full image-to-recovered-path success"; calibrated refusals count as unsuccessful recovery. The equal 2-TEST source population has already been inspected in earlier V27/V28, so all V30 TEST numbers are descriptive posthoc, never preregistered confirmation.
