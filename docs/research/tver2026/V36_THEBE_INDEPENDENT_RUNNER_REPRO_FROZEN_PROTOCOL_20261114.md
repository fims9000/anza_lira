# V36: независимая повторная проверка воспроизводимости Thebe TRAIN, без открытия TEST7

**Протокол зафиксирован 14 ноября 2026 года до запуска V36 и до получения его результатов.** Базовая версия — [V35](https://github.com/fims9000/anza_lira/actions/runs/43603004021), которая обучала две одинаково инициализированные копии каждой архитектуры *в рамках одного процесса*, получив битово равные веса. Это ещё не доказывает воспроизводимость на **другом** GitHub runner. V33 уже показала большой разброс при первоначальном многопоточном режиме (ANZA 14/20 и 6/20, U-Net 4/20 и 0/20 на фиксированных SEG-CAL случаях). Прежние результаты **не исправлять и не замещать**.

## Независимая проверка

1. Взять новый GitHub runner, повторить **без изменений** `scripts.tver_v35_thebe_determinism`: 600 одних и тех же TRAIN-патчей и 96 одних и тех же SEG-CAL-патчей, одинаковые seed, фиксированные исходные официальные TRAIN1/VAL1 MD5, один CPU-поток, MKLDNN disabled, deterministic_algorithms=True, torch 2.5.1+cpu, одинаковый NumPy.
2. Сначала скачать оригинальный immutable артефакт V35 из run 43603004021, а не копировать вручную список ожидаемых хэшей. Сравнить два JSON независимо от V35 обучающего кода:
   - SHA256 всех 600 TRAIN-патчей и 96 SEG-CAL-патчей;
   - train-only нормировку;
   - версии программ и флаги детерминизма;
   - ANZA и U-Net raw sorted state_dict tensor SHA256 (НЕ только torch.save контейнер);
   - первый/последний средний TRAIN-loss и каждую строку пороговой SEG-CAL pixel-метрики.
3. Сравнение проводить отдельно для каждого из двух прогонов в каждом runner, то есть 2 × 2 независимых сравнений для двух архитектур.
4. При любом расхождении записать точное поле и прекратить заявления о воспроизводимой тренировке. Не менять seed, пороги или learning rate после проверки. Даже точная воспроизводимость на двух runner **не доказывает статистического превосходства ANZA** — для этого нужны несколько независимых инициализаций и внешний сегментационный TEST.
5. Ни официальный `seistest7.npz`, ни `faulttest7.npz` не скачивать, не открывать, не хэшировать содержимое TEST; ограничиться TRAIN1/VAL1. Проверка касается программного воспроизведения, а не геологической идентичности разломов.

## Контроль выводов

V34 по отдельной REL-CAL группе из 60 валидирующих срезов получил **314 истинных предсказанных TRAIN-пар** и успешное обучение P0; но все сравниваемые модели при строгой CAL-ошибке выбрали **полный отказ**. Поэтому даже положительная V36 не разрешает открыть TEST7 и не превращает 0 принятых связей в результат по восстановлению. Требуется новое зафиксированное исследование самой селекции пар, затем независимая калибровка и только после выполнения критериев — однократный внешний TEST.
